## 真实摸出的产品质量缺陷

### 🔴 P0 业务缺陷（修复前必出问题）

**`acceptInvite` 过期邀请码事务回滚导致状态卡死**

- 现象：邀请码 expireAt < now → 走"已过期"分支 → ServiceException 抛错 → 外层 @Transactional 回滚 → 之前 `inviteService.update(invite)` 把 status=2 的更新也被回滚 → 邀请码永远卡 status=0
- 触发：第 2 次扫同一过期码时，会再次走 expireAt 校验，永远抛"已过期"，不会走"已失效"短路
- 业务影响：用户反复扫码重复失败，admin 端无法看到该码的"已过期"标签，平台数据不一致
- 修复：抽出 `markExpired(Long inviteId)` 走 `Propagation.REQUIRES_NEW` 独立事务，先提交 status=2 再抛错
- 文件：
  - `IMerchantStaffInviteService.java` 新增 `markExpired` 接口
  - `MerchantStaffInviteServiceImpl.java` 新增 `@Transactional(propagation=REQUIRES_NEW)` 实现
  - `ApiMerchantStaffController.acceptInvite` 改调 `markExpired`

### 🟡 P1 产品体验缺陷

**admin 端 staffInvite 二维码按钮对失效态无防护**
- 现象：已用/已过期/已停用邀请码仍可点击"二维码" → 浪费一次微信 wxacode 调用
- 修复：按钮 `:disabled="scope.row.status !== '0'"` + 文案变 "已失效" + showQrcode 前置 `msgWarning` 拦截
- 状态映射补 status=3 "已停用" 标签

**小程序 scan 页没有重试/防重/确认弹窗**
- 现象：连续点击扫码按钮会触发多次 `wx.scanCode`；扫错二维码直接 reject，无确认弹窗
- 修复：
  - `data.scanning` 防重点击
  - 解析后 `wx.showModal` 二次确认加入
  - catch 分支按业务错误码（已过期/已失效/与门店不匹配）分别弹模态框提示

**scene 解析脆弱**
- 现象：原代码只用 `substring(queryIdx + 6)` 截取整个 query 段，URL 含其他参数时会污染 scene
- 修复：抽出 `utils/inviteScene.js` 纯函数，正确解析 `?key=val&key2=val2` 格式，URL 解码冒号 %3A，校验段数/数字段/短码长度 4-8

## 产品级代码标准

### SQL 种子
- `sql/biz_product_industry_sync_safe.sql` 新建，**MySQL 5.7 兼容**（原 seed 用 `UPDATE...JOIN` 5.7 不支持）
- 幂等可重跑（`SET NAMES utf8mb4` + 游标循环 + WHERE 条件）
- 兜底策略：未匹配 → `industry_code='OTHER'`（避免 NULL 业务异常）
- 业务断言：`SELECT ... GROUP BY` 输出行数/空值/兜底统计，便于 CI 集成

### 业务事务
- 状态机变更走 `REQUIRES_NEW` 独立事务，避免外层回滚污染
- 邀请码状态 0→1（已用）/ 0→2（过期）/ 0→3（停用）单向迁移
- 每次 acceptInvite 强校验 mid/sid 与邀请码一致，防钓鱼链接串号

### 前端
- 按钮 disabled 状态显示明确（"已失效"）
- 错误码 → 用户可读文案映射（`REASON_MSG`）
- 防重点击（scanning flag）
- 模态框区分可恢复错误（已过期/已失效/串号）vs 一次性 toast

### 测试
- 22 个 vitest 单测覆盖 `parseInviteScene` 全部分支（含防 XSS/注入）
- 14 个 smoke 端到端覆盖 acceptInvite 状态机 + scene 边界
- 1 个 SQL 集成测试（industry sync）输出 3 项断言
