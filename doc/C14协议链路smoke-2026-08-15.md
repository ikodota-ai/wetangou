## 摸底附带发现：AgreementMapper XML 嵌套风险

```xml
<if test="merchantId != null ">
  <if test="params != null and params.merchantIdsIn != null">
    <choose> ... and a.merchant_id = #{params.merchantIdsIn} </choose>
  </if>
 and a.merchant_id = #{merchantId}</if>   <!-- merchantId 在外层 if 的 else 分支，结构错乱 -->
```

外层 if 内嵌另一个 if，闭合后又写 ` and a.merchant_id = #{merchantId}`，看似在嵌套里实际在外层 if 的 else 分支。当前 controller 层 `query.setStatus("0")` 兜底了 status 过滤，所以 smoke 端到端 PASS。但如果未来去掉 controller setStatus 或新增 merchantId 入参，会立即爆。

**建议**：下轮抽空修一下 mapper（2 行：把 `and a.merchant_id = #{merchantId}` 提到外层 if 的 then 分支），风险低工作量大可单独立项。
