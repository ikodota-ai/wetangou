## A. 业务正确性（最优先，可能影响生产）

### A1. 业务表 Service 接 TenantContext，按身份过滤
**场景**：agent 账号登录后，调 `/biz/order/list` 接口拿订单数据；当前 Service 没接 TenantContext 拼 merchant_id/agent_id 过滤，会返回所有商户订单。
**问题**：跨租户数据泄漏——代理商能看到别家代理的订单。
**当前覆盖**：CategoryServiceImpl 等 Service 在 `selectXxxList` 没加 `merchant_id` 过滤。
**解决方法**：
1. 在 Service 层统一加 `@TenantFilter` 注解 + AOP 切面自动拼 SQL
2. 或在 `Controller` 入口处统一调 `TenantService.assertDataScope(entity)` 强校验
3. 推荐：前者（AOP 透明），工作量 1.5 天
**优先级**：高

### A2. 提现冷静期结算联动余额
**场景**：提现申请 → 等待冷静期 → 管理员审核 → 入账。当前"冷静期"步骤只把 `frozen_amount` 标记为"可提现"，但**没联动** `available_amount += amount`、`withdraw_amount += amount`。
**问题**：会员申请提现后，前端显示"已提现 X 元"，但实际账户余额没变化，重复申请会超提。
**解决方法**：补 `SettleCommissionTask` / 提现审核回调的余额联动逻辑
**优先级**：高

### A3. release UI 完善
**场景**：平台给某商户发布小程序（miniprogram7）时，UI 流程只到"上传代码"，没有"提交审核→审核回调→发布上线"的完整流程。
**当前**：mpRelease 表有 `status` 字段但 UI 没暴露。
**解决方法**：
1. 后台 `biz/mprelease` 页加按钮：上传 / 提交审核 / 发布上线 / 回退
2. 后端 mpReleaseService 调微信"第三方平台" API（commit + release）
3. 工作量 1 天
**优先级**：中

### A4. Web 后台员工工作台
**场景**：员工账号（store_staff）能登录小程序核销，但 Web 后台没给员工入口；商家主账号开新员工只能走 sys/user 列表。
**当前**：员工权限 role=6 有绑定菜单，但没专门的 `/staff/index` 入口。
**解决方法**：
1. Web 后台新增 `/staff/index` 工作台
2. 路由 + 菜单按 `userType='3'`（员工）过滤
3. 工作量 0.8 天
**优先级**：中

### A5. 门店 logo 修复
**场景**：门店管理列表里 logo 显示不出来（OSS / 本地存储配置不一致）。
**当前**：表里有 logo 字段，存储用本地（`/profile/upload`），但配置 `spring.servlet.multipart.location` 路径有变化。
**解决方法**：统一用 MinIO 或 OSS，配置文件 `ruoyi-file-dev.yml`
**优先级**：低

## B. 体验优化

### B1. 登录入口 userType 分流（前端）
**场景**：用户登录时不强提示"你是平台/代理/商户"，登录后跳转工作台感知弱。
**当前**：vuex 有 `userType`，但登录页 login.vue 没显示。
**解决方法**：
- login.vue 顶部加 3 选 1 tabs（仅展示当前身份）
- 工作台跳转在 `resolveEntryPath` 已完成
- 工作量 0.2 天
**优先级**：低

### B2. 商品详情小程序分享海报
**场景**：用户点击"分享"按钮生成分享海报，目前是占位，没真实 wx.canvas 绘制。
**解决方法**：用 `wx.createCanvasContext` + 后端生成 base64 海报图
**优先级**：低

### B3. 小程序 promoter/withdraw 文案优化
**场景**：提现后前端文案"已提现"，但实际是"等待审核"。
**解决方法**：文案区分"申请中 / 已通过 / 已到账 / 已驳回"
**优先级**：低

### B4. 业务表选门店交互推广到全部表单
**场景**：刚才已改 4 个表单（commission/bill/category/booking），还有 8 个含 `form.storeId` 的表单可继续推广。
**剩余文件**：agreement/distributor/member/user/voucher/bookingmember/withdraw/record/rule/album
**工作量**：0.5 天
**优先级**：低

**工作量**：0.2 天

## D. 工程

### D1. Java 17 字节码强制（你已要求）
**当前**：JDK 25 编译默认是 17 字节码，但要确保 `<maven.compiler.release>17</maven.compiler.release>` 在 pom.xml。
**核查**：所有模块 pom.xml 检查 `<java.version>` 与 `maven.compiler.release`
**工作量**：0.1 天

### D2. 前端 BizSelect 支持"按类型远程搜索"扩展
**场景**：未来要加新业务类型（如选优惠券 voucher、选预约 booking）时不用改组件。
**当前**：BizSelect CONFIG 已支持 5 种类型，但加新类型要改源码。
**解决方法**：用 webpack require.context 自动注册
**工作量**：0.3 天

### D3. README 重写（GitHub）
**场景**：GitHub 上 README 是默认 RuoYi 模板，没体现 wetangou 业务架构。
**解决方法**：写一份完整 README，包括功能/技术栈/部署/测试账号/截图
**工作量**：0.5 天

### D4. CI 流水线（GitHub Actions）
**场景**：现在手动 build + push。
**解决方法**：加 `.github/workflows/build.yml`，每次 push 自动跑 mvn + npm build
**工作量**：0.3 天
