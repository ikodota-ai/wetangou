## 1. 系统初始化

### 1.1 环境要求

| 项目 | 最低 | 推荐 |
|---|---|---|
| JDK | 17 | 21 |
| MySQL | 8.0 | 8.0+ |
| Redis | 6.0 | 7.0+ |
| Node | 16 | 18 LTS |
| 操作系统 | Linux/macOS | Linux (Ubuntu 22.04 / CentOS 8) |

### 1.2 首次部署步骤

```bash
# 1. 创建数据库（utf8mb4）
mysql -uroot -p -e "CREATE DATABASE ry_vue DEFAULT CHARSET utf8mb4 COLLATE utf8mb4_unicode_ci;"

# 2. 按顺序执行 SQL（全部幂等）
mysql -uroot -p ry_vue < sql/ry_20260417.sql
mysql -uroot -p ry_vue < sql/biz_tables.sql
mysql -uroot -p ry_vue < sql/biz_menu_reorganization.sql
mysql -uroot -p ry_vue < sql/biz_tenant_tables.sql
mysql -uroot -p ry_vue < sql/biz_tenant_upgrade.sql
mysql -uroot -p ry_vue < sql/biz_tenant_menu.sql
mysql -uroot -p ry_vue < sql/biz_mpconfig_menu.sql
mysql -uroot -p ry_vue < sql/biz_distributor_invite.sql
mysql -uroot -p ry_vue < sql/biz_booking_upgrade.sql
mysql -uroot -p ry_vue < sql/quartz.sql
mysql -uroot -p ry_vue < sql/biz_banner.sql
mysql -uroot -p ry_vue < sql/biz_commission_settle_job.sql
mysql -uroot -p ry_vue < sql/biz_wxconfig_init.sql   # 默认 seed，商户级支付凭证留空

# 3. 配置 application-druid.yml（数据库 / Redis）
vim ruoyi-admin/src/main/resources/application-druid.yml

# 4. 启动后端
mvn clean package -DskipTests
java -jar ruoyi-admin/target/ruoyi-admin.jar

# 5. 启动后台
cd ruoyi-ui && npm install && npm run dev
# 访问 http://localhost:80，账号 admin/admin123
```

### 1.3 升级到生产环境必做清单

- [ ] 修改 admin 默认密码（`系统管理 → 用户管理 → admin → 重置密码`）
- [ ] 修改 `application.yml` 中 `ruoyi.profile` 指向生产上传目录
- [ ] 确认 `wx.miniapp.mockEnabled=false` 与 `wx.pay.mockEnabled=false`（默认已关）
- [ ] 关闭 swagger：`application.yml` 中 `swagger.enable=false`
- [ ] 启用 HTTPS（建议 Nginx + Let's Encrypt / 阿里云 SSL）
- [ ] 修改 Redis 密码、JWT 密钥
- [ ] 备份策略：数据库每日全量 + binlog 增量

### 1.4 默认账号

| 账号 | 密码 | 角色 | 备注 |
|---|---|---|---|
| admin | admin123 | 平台 | 首次登录后必须改密 |
| ry | 123456 | 平台 | 演示账号（生产删除） |

## 2. 第三方平台代发布流程

> **核心目的**：平台统一管理多个商户（代理商名下）的小程序发布，避免每个商户都走一次完整审核。

### 2.1 前置准备（一次性）

#### 2.1.1 注册第三方平台

1. 用**公司主体**的微信开放平台账号登录 https://open.weixin.qq.com
2. 进入「管理中心 → 第三方平台 → 创建第三方平台」
3. 填写基本信息：
   - 平台名称：例 `Wetangou 代发布平台`
   - 平台简介：例 `为本地餐饮商户提供小程序代开发与代发布服务`
   - 平台 logo、官网：自行准备
4. 资质审核：需 300 元 / 年，3-7 个工作日通过
5. 审核通过后获得：
   - `componentAppId`（第三方平台 AppId，wx 开头的 18 位）
   - `componentAppSecret`（第三方平台 Secret）

#### 2.1.2 配置服务器域名（重要）

在「第三方平台详情 → 开发配置 → 授权事件接收 URL / 消息校验 Token / 消息加解密 Key」中：

| 项 | 值 | 说明 |
|---|---|---|
| 授权事件接收 URL | `https://your-domain.com/api/wxopen/notify` | 接收 component_verify_ticket + 授权通知 |
| 消息校验 Token | 自定义 32 位字符串 | 填到「小程序平台配置」的 componentToken |
| 消息加解密 Key | 自定义 43 位字符串 | 填到 componentAesKey |
| 授权后回调域名 | `your-domain.com` | 商户授权后跳转的根域名 |

> ⚠️ **必须**：URL 必须 HTTPS，证书有效；本地调试可用 ngrock / frp 内网穿透。

#### 2.1.3 创建代码模板

1. 用任一商户 appid 完整开发一个小程序（含 `app.js` / `pages` / `ext.json` 等）
2. 提审一次（用模板库要求的主代码包）
3. 审核通过后，在「第三方平台 → 代码管理」中提取为**代码模板**，获得 `templateId`

### 2.2 后台配置（平台首次使用）

#### 2.2.1 填写「小程序平台配置」

路径：`团购运营 → 平台配置 → 小程序平台配置`

| 字段 | 填写 | 示例 |
|---|---|---|
| 开放平台第三方 AppId | 2.1.1 拿到的 componentAppId | `wxabc123...` |
| 开放平台第三方 Secret | 2.1.1 拿到的 componentAppSecret | `abc123...` |
| 开放平台消息校验 Token | 2.1.2 自定义的 token | `WetangouVerifyToken2026` |
| 开放平台消息加密 Key | 2.1.2 自定义的 aesKey（43 位） | `43位字母数字` |
| 小程序代码模板 ID | 2.1.3 拿到的 templateId | `templateId` |
| 授权回调域名 | 2.1.2 配置的授权回调域名 | `wetangou.com` |
| 小程序接口域名 | 后端 API 实际域名 | `https://api.wetangou.com` |

> `component_verify_ticket` 由微信每 10 分钟自动推送到「授权事件接收 URL」，**不需要手动填写**。

#### 2.2.2 验证配置

保存后访问「小程序平台配置」页面，看是否正常显示。若：

- 顶部提示「最近一次 ticket 推送：5 分钟前」→ ✅ 正常
- 提示「暂无 ticket 推送记录」→ 检查回调 URL 是否公网可达、Token/AesKey 是否一致

### 2.3 商户授权流程

#### 2.3.1 商户准备

1. 商户用**法人微信号**扫码进入 `https://mp.weixin.qq.com`
2. 进入「设置 → 第三方平台授权管理」点击「授权」
3. 扫码确认授权，授权页面会跳回 `https://your-domain.com/wxopen/auth-callback?auth_code=xxx`

> **注意**：商户主体必须先完成微信小程序**主体注册与认证**（300 元/年），代发布**不能免除**主体资质。

#### 2.3.2 平台登记授权

1. 商户授权后回调，后端自动存 `biz_mp_auth`：
   - `appid`（被授权方小程序 appid）
   - `authorizer_refresh_token`（**必须加密存储**）
   - `func_info`（权限集：开发管理与数据分析权限）
2. 后台「小程序平台配置」页面应能看到该商户的授权状态

#### 2.3.3 维护商户 appid

进入「团购运营 → 租户管理 → 商户管理」编辑该商户：

| 字段 | 填写 |
|---|---|
| 小程序 AppId | 2.3.2 拿到的 appid（与授权一致） |
| 小程序 AppSecret | 商户主体的 secret（在 mp.weixin.qq.com → 开发管理） |
| mock 登录开关 | 保持 `0 关闭`（生产必须） |

> 系统会校验 appid 全局唯一，重复会拒绝。

### 2.4 代发布单条流程

#### 2.4.1 后台发起代发布

路径：`团购运营 → 租户管理 → 小程序代发布 → 新增`

| 字段 | 填写 | 校验 |
|---|---|---|
| 所属商户 | 下拉选授权过的商户 | 必选 |
| 小程序 appid | 自动填充 | 必填 |
| 代码模板 ID | 留空则用平台默认 | 选填 |
| 商家自定义 extJson | 留空则后端自动生成 | 选填 |
| 版本号 | 1.0.0（语义化版本） | 必填 |
| 版本说明 | 变更内容 | 必填 |

点击「提交」→ 状态置为 `draft`（草稿）。

#### 2.4.2 提交流程（按顺序）

| 步骤 | 操作 | 后端动作 | 状态变化 |
|---|---|---|---|
| 1 | 点击「生成体验版」 | 调微信 `commit` + `getqrcode` | `draft → committed` |
| 2 | 扫码体验 | 用户扫体验码 | — |
| 3 | 点击「提交审核」 | 调微信 `submit_audit` | `committed → audit` |
| 4 | 等待审核结果 | 微信审核（1-7 天） | — |
| 5 | 审核通过 | 微信回调 | `audit → passed` |
| 6 | 点击「发布上线」 | 调微信 `release` | `passed → released` |
| 7 | 点击「回退」 | 调微信 `revertcoderelease` | `released → rollback` |

#### 2.4.3 异常处理

| 异常 | 处置 |
|---|---|
| 体验版扫码空白 | 检查 `ext.json` 中 `extAppid` 是否与商户 appid 一致；检查 `appid` 是否在 mp.weixin.qq.com 设置了「服务器域名」 |
| 审核被拒 | 在 `audit_status=3` 详情中查看 `audit_reason`；修正后点「重新提审」（自动从 failed 状态允许重新提交） |
| 撤回审核 | 状态 `audit`（审核中）时可点「撤回」→ `audit → undo` |
| 发布失败 | 检查 API 凭证 + 商户是否仍有授权（refresh_token 90 天未用会过期，需商户重新授权） |

### 2.5 批量升级（多商户模板升级）

> ⚠️ **生产前必修**：模板升级是逐个 appid 循环调用，**目前是同步执行**，**没有失败重试队列**。建议在业务低峰期进行。

```
1. 后台「小程序平台配置」修改 templateId / apiBaseUrl
2. 「小程序代发布 → 新增」选「批量模式」（如支持）
3. 后台依次 commit + audit + release 每个商户
4. 失败的商户记录在「失败重试」列表，运维手动重试
```

**建议（下一轮迭代）**：
- 改造为异步任务（挂 ruoyi-quartz）
- 失败重试 3 次 + 告警邮件
- 全量升级的进度可视化

## 3. 微信支付配置

### 3.1 商户开通支付

> 每个商户在微信支付商户平台（pay.weixin.qq.com）单独申请商户号。

#### 3.1.1 申请

1. 商户登录 `https://pay.weixin.qq.com`
2. 「产品中心 → 申请开通 → JSAPI 支付」（小程序内支付必须）
3. 准备材料：营业执照、法人身份证、对公账户
4. 审核 1-3 个工作日，获得：
   - `mchId`（商户号，10 位数字）
   - `appId`（已绑定的 appid）

#### 3.1.2 申请 APIv3 证书

1. 商户平台「账户中心 → API 安全 → 申请 API 证书」
2. 下载工具生成 CSR，提交后获得：
   - `apiclient_cert.pem`（证书）
   - `apiclient_key.pem`（私钥）→ **妥善保管，**上传到服务器，**不要入库**
   - `certSerialNo`（证书序列号，40 位 hex）

#### 3.1.3 设置 APIv3 密钥

1. 商户平台「账户中心 → API 安全 → 设置 APIv3 密钥」
2. 设置 32 位字符串，**保存到安全位置**
3. 填到后台「商户管理 → 微信配置 → APIv3 密钥」

#### 3.1.4 配置支付回调

1. 后台「商户管理 → 微信配置 → 支付回调地址」填：
   - `https://your-domain.com/api/pay/notify/{merchantId}`（推荐，多商户路由清晰）
   - 或统一 `https://your-domain.com/api/pay/notify`（按 out_trade_no 反查）
2. 商户平台「产品中心 → 开发配置 → 支付回调 URL」**填同样地址**（必须一致，否则回调不达）

### 3.2 后台登记

路径：`团购运营 → 租户管理 → 商户管理 → 编辑 → 微信配置 Tab`

| 字段 | 填写 |
|---|---|
| 支付方式 | 0 商户自有商户号（推荐，无二清） / 1 平台统一收款分账（待资质） |
| 支付商户号 | 商户号 mchId |
| 支付 AppId | 支付绑定的 appid（一般同小程序 appid） |
| 证书序列号 | 3.1.2 拿到的 certSerialNo |
| 私钥路径 | 服务器上 apiclient_key.pem 的**绝对路径**，例如 `/data/wxpay/mch123/key.pem` |
| APIv3 密钥 | 3.1.3 设置的 32 位字符串 |
| 支付回调地址 | 3.1.4 配置的回调 URL |

> 私钥文件须：
> - 由应用账号可读（`chown app:app key.pem && chmod 600`）
> - 不入库（不提交到 git）
> - 服务器间同步用 scp/rsync，不要走 HTTP

### 3.3 测试支付

> ⚠️ **全部环境（含 dev）已关闭 mock 兜底**（commit `6120263f`）。
> 测试支付必须用微信支付沙箱环境或真实商户号的小额支付。

1. 申请「微信支付沙箱」：`https://pay.weixin.qq.com/wiki/doc/api/jsapi.php?chapter=23_1`
2. 用沙箱商户号配置一遍上面的字段
3. 小程序端下单，金额填 0.01 元

### 3.4 支付故障排查

| 现象 | 排查 |
|---|---|
| 调起支付报「商户号错误」 | 检查 mchId 与 appId 是否在微信支付商户平台绑定 |
| 报「签名错误」 | 检查 certSerialNo、privateKeyPath、apiV3Key 是否正确；私钥文件权限 600 |
| 报「回调地址不合法」 | 回调 URL 必须是 HTTPS 且在商户平台「产品中心 → 开发配置」中配置一致 |
| 回调没收到 | Nginx 防火墙 / 证书无效 / 微信通知频率高被限频（同一回调失败 5 次后不再通知） |
| 回调报「解密失败」 | apiV3Key 错误；用 `mch_id=xxx&nonce=xxx&...` 在商户平台「回调通知签名校验工具」验证 |

## 4. 代理商开单与额度管理

### 4.1 代理商开通

1. 后台「系统管理 → 用户管理」创建代理商账号（设置角色为「代理商」）
2. 「团购运营 → 租户管理 → 代理商管理 → 新增」：
   - 代理商名称、联系电话
   - 额度：可开通的商户数（例 10）
   - 到期时间：服务有效期
3. 系统自动写 `biz_merchant_user` 把 user_id 绑到 agent_id

### 4.2 代理商缴费

#### 4.2.1 登记缴费单

1. 代理商登录后台（权限范围内）
2. 「团购运营 → 租户管理 → 代理商缴费 → 登记」
3. 填：缴费金额、缴费月数、起始日期、备注
4. 状态置为 `0 待确认`

#### 4.2.2 平台确认

1. 平台管理员登录
2. 「代理商缴费 → 待确认」列表 → 点击「确认」
3. 后端自动：
   - `paid_amount += amount`
   - `expire_time` 延 12 个月
   - 累计已缴费
4. 状态置为 `1 已确认`

> ⚠️ 已确认单**不能再次确认**、**不能修改金额**、**不能删除**。

### 4.3 代理商开通商户

代理商账号登录 → 「团购运营 → 租户管理 → 商户管理 → 新增」

| 字段 | 填写 | 校验 |
|---|---|---|
| 商户名称 | 自定义 | 必填 |
| 小程序 appid | wx 开头 18 位 | 全平台唯一 |
| 联系人、电话 | 自定义 | 必填 |

后端自动：
- `agent_id` 强制设为当前代理商
- 校验 `used_quota < merchant_quota`（额度满则拒绝）
- 通过后 `used_quota + 1`

### 4.4 额度不足

代理商登录后看到「额度用量进度条」：0/10 → 10/10 后无法再开商户，需先向平台缴费。

## 5. 商户开通与代发布

商户开通走「代理商开单」流程，详见 [4.3](#43-代理商开通商户)。商户开通后需做：

1. **配置微信小程序**：见 2.3 节
2. **配置微信支付**：见 3 节
3. **配置门店**：见 5.1
4. **商品上架**：见 5.2
5. **小程序代发布**：见 2.4

### 5.1 门店管理

路径：`团购运营 → 门店商品 → 门店管理`

| 字段 | 必填 | 备注 |
|---|---|---|
| 门店名称 | 是 | 唯一 |
| 门店地址 | 是 | 顾客端显示 |
| 经度 / 纬度 | 是 | 用于「最近门店」和地图导航 |
| 营业时间 | 否 | 用于「客服/营业」展示 |
| 客服电话 | 否 | 用于一键拨号（@Sensitive 脱敏） |
| 服务设施 | 否 | 字典多选：堂食/外带/停车/WiFi |

### 5.2 商品上架

路径：`团购运营 → 门店商品 → 商品管理`

| 字段 | 必填 | 备注 |
|---|---|---|
| 商品名称 | 是 | 顾客端显示 |
| 所属门店 | 是 | 多选（一个商品可多门店） |
| 价格 | 是 | 精度 2 位小数 |
| 库存 | 否 | 0 或 null = 不限 |
| 有效期（天） | 否 | 核销后多少天有效，默认 30 |
| 状态 | 是 | 0 上架 / 1 下架 |

### 5.3 协议维护

路径：`团购运营 → 门店商品 → 协议管理`

发布前必须维护：
- 用户协议（`type=user`）
- 隐私政策（`type=privacy`）

**生效机制**：
- 平台级（`merchant_id=0`）全商户可见
- 商户可另建自己的协议（`merchant_id=本商户`）
- 顾客登录时按 merchantId 自动选本商户协议；无则用平台级

## 6. 首页 Banner 后台维护

路径：`团购运营 → 平台配置 → 首页 Banner`

### 6.1 字段说明

## 7. 佣金冷静期与提现审核

### 7.1 佣金状态机

```
订单支付成功
    ↓
biz_commission.status = 0（待结算）
推客 frozenAmount += amount（进入冻结）
推客 totalCommission += amount（累计佣金）
    ↓
7 天冷静期（commissionRule.settleDays）
    ↓
Quartz 每天 03:00 扫描：
    UPDATE biz_commission 
    SET status=1, settle_time=NOW()
    WHERE status=0 AND create_time + 7 day <= NOW()
    ↓
推客 availableAmount += amount（可提现）
推客 frozenAmount -= amount（释放冻结）
```

> ⚠️ **当前已知问题**（commit `fa6dc2e8` 的 TODO 边界）：
> Quartz Job **仅修改 commission.status**，**未联动推客余额**。
> 修复方法见 [质量评估报告 M1](质量评估与完整性报告.md)。

### 7.2 提现申请

#### 7.2.1 推客申请

小程序端 `pages/promoter/withdraw`：

| 字段 | 必填 | 备注 |
|---|---|---|
| 提现类型 | 是 | 0 微信零钱 / 1 支付宝 / 2 银行卡 |
| 提现金额 | 是 | ≤ availableAmount |
| 账户 | 是 | 微信实名 / 支付宝账号 / 银行卡号 |
| 账户姓名 | 是 | 收款人姓名 |

后端：
- `availableAmount -= amount`（立刻扣减）
- `biz_withdraw.status = 0（待审核）`

#### 7.2.2 平台审核

后台「团购运营 → 推客分销 → 提现申请」：

| 操作 | 动作 |
|---|---|
| 通过 | 调 `SettlementService.approveWithdraw`：status=1，withdrawAmount += amount |
| 驳回 | 调 `SettlementService.rejectWithdraw`：status=2，availableAmount += amount（退回） |

### 7.3 佣金规则配置

路径：`团购运营 → 推客分销 → 佣金规则`

| 字段 | 说明 |
|---|---|
| 规则名称 | 自定义 |
| 门店 | 0 = 全平台 |
| 分类 | 可选 |
| 商品 | 可选 |
| 推客等级 | 默认 1 |
| 佣金比例 | 0-100% |
| 冷静期（天） | 默认 7 |

**匹配优先级**：`商品 > 分类 > 门店 > 全平台`，详见 `ApiCommissionService.matchRate`。

## 10. 常见问题 FAQ

### Q1：顾客登录提示「小程序未接入或已停用」

**原因**：后端 `biz_merchant.appid` 找不到当前 appid。  
**修复**：检查 `utils/config.js` 的 APPID 是否与后台「商户管理 → 微信配置」一致。

### Q2：代理商登录后看不到菜单

**原因**：代理商角色权限未分配。  
**修复**：后台「系统管理 → 角色管理 → 代理商 → 分配菜单」，参考 `sql/biz_tenant_menu.sql`。

### Q3：佣金记录无数据

**原因**：订单没有绑定 `distributorId`。  
**修复**：下单时带 `distributorId` 参数（推客分享链接带 `invite_by=memberId`）。

### Q4：预约时段选择空白

**原因**：`biz_booking_slot_config` 未配置时段。  
**修复**：执行 `sql/biz_booking_slot_config.sql` 或后台「预约管理 → 时段配置」。

### Q5：核销码扫描提示「订单不存在」

**原因**：核销码被部分遮蔽或字符识别错误。  
**修复**：手动输入完整 12 位核销码（订单详情可查）。

### Q6：支付后订单状态没变

**原因**：微信回调地址不达或解密失败。  
**修复**：
- 后端日志搜索 `WxPayService` 关键字
- 商户平台「产品中心 → 开发配置」核对回调 URL
- 用回调通知签名校验工具验证

### Q7：首页 banner 不显示

**原因**：
- `merchantId` 没传 → 走「全平台」模式看不到本商户专属
- `status` 未启用
- 生效时间窗未到

**修复**：
- 后台「首页 Banner」核对 status='0'、activeFrom<=now()、activeTo>=now()

### Q8：手机号显示「***」

**原因**：`@Sensitive` 脱敏生效。  
**说明**：脱敏对 admin 自动看明文（详见 `doc/多商户与代理商改造方案.md` §4.5）；其他角色看 `138****1234` 格式是**正常的**。

### Q9：后台菜单不显示

**原因**：当前账号没有该菜单权限。  
**修复**：「系统管理 → 角色管理 → 当前角色 → 分配菜单」勾选 + 重启登录。

### Q10：多商户间数据串了

**原因**：`TenantSqlInterceptor` 没生效或被 `@IgnoreTenant` 误标。  
**排查**：
- 检查 `LoginUser.tenantContext` 是否带 `merchantId`（调试模式下加断点）
- 检查 Mapper 方法 / 接口是否有 `@IgnoreTenant` 误标
- 确认 `biz_*` 表在 `TenantTableRegistry.ISOLATED_TABLES` / `SHARED_TABLES` 内

## 11. 故障应急处理

### 11.1 紧急停服

```bash
# 1. 摘流量（Nginx / SLB）
vim /etc/nginx/conf.d/wetangou.conf
# upstream 改为一台空 server

# 2. 停后端
./ry.sh stop

# 3. 通知用户（小程序客服消息 / 公众号推文）
```

### 11.2 数据库故障

```bash
# 1. 检查从库是否可用
mysql -uroot -p -h slave.wetangou.com -e "SELECT 1;"

# 2. 切换到从库
# 改 application-druid.yml → 数据源 → 重启

# 3. 联系 DBA 修复主库
```

### 11.3 支付故障

1. **下单失败**：暂停小程序下单功能，平台发公告
2. **回调失败**：手动对账（按订单号逐笔核对微信商户平台流水）
3. **重复扣款**：发起退款（商户平台「订单管理 → 退款」）

### 11.4 Redis 故障

```bash
# 1. 重启 Redis
systemctl restart redis

# 2. 重建缓存（租户上下文、WxMaConfig 缓存）
# 重启后端即可（业务自动回源 DB）
```

### 11.5 微信接口异常

- **登录失败**：后端日志检查 `wxMaService.code2Session` 返回码
- **支付失败**：商户平台「账户中心 → API 安全 → 证书状态」检查证书有效期
- **代发布失败**：第三方平台「消息加密 Key」重新生成并同步到后台

## 12. 多商户 appid 链路排查与自愈

> 适用场景：小程序请求 `/api/store/list` 返回空，或日志里出现
> `X-App-Id=xxx 未匹配到有效商户` 警告。

### 12.1 链路原理

```
小程序请求
   │  X-App-Id: wx9e147c4e2151b123
   ▼
MemberAuthInterceptor.resolveTenantByAppid
   │ ① header.X-App-Id
   │ ② request param ?appid=
   │ ③ 查 TenantService.getMerchantByAppid → Redis 缓存 → DB
   ▼
命中 → TenantContextHolder.set(merchantId)
未命中 → fallback 到 TenantConstants.DEFAULT_MERCHANT_ID=1
   ▼
TenantSqlInterceptor 自动给所有 biz_* SQL 加 WHERE merchant_id = ?
```

链路完全 OK，问题只可能是：**DB 里 `biz_merchant.appid` 与小程序编译期 appid 不一致**，
或 **store 数据挂在了别的 merchant_id 下**。

### 12.2 三步定位

跑 `miniprogram7/DEBUG_DIAGNOSE.sql`：

1. 查 `biz_merchant` 的 appid 是否为空
2. 查 `biz_store` 的 store_id=200 挂在哪个 merchant_id
3. 查所有 appid 是否有重复

### 12.3 三种自愈

| 场景 | 修复 SQL | 备注 |
| --- | --- | --- |
| 默认商户 appid 为空 | `UPDATE biz_merchant SET appid='wx9e147c4e2151b123' WHERE merchant_id=1;` | 改完重启后端让 Redis 缓存重建 |
| store 挂错商户 | `UPDATE biz_store SET merchant_id=1 WHERE store_id=200;` | 仅限演示数据，生产慎用 |
| sys_config 缺 key | 跑 `sql/biz_tenant_upgrade.sql` 步骤 4.2.5（已自动 upsert） | 重跑整个升级脚本即可 |

### 12.4 永久兜底（已提交）

- `sql/biz_tenant_upgrade.sql` 步骤 4.2.5：sys_config 缺 `wx.miniapp.appId` 时自动写入 `wx9e147c4e2151b123`
- 步骤 4.3.1：默认商户 appid 仍为空时强制覆盖为 `wx9e147c4e2151b123`
- 这两个步骤让「按小程序配置的 appid 查找商户」链路**自打开升级脚本就打通**，
  不再依赖 sys_config 老 RuoYi 单商户 key。

### 12.5 多商户 appid 共存方案

如果未来接入第二个商户（B 商户 appid=wxBbb...）：

1. 后台「商户管理」新增商户，填 appid=wxBbb...
2. 后台「微信配置」填 B 商户的支付凭证
3. B 商户自己用 B appid 的小程序登录，自动解析到 B merchant_id
4. 同一份后端 jar 支持 N 个 appid，DB 里 `biz_merchant` 多行不冲突

`MemberAuthInterceptor` 的 `getMerchantByAppid` 已经按 `biz_merchant.appid` 反查，
**这就是"按小程序配置的 appid 查找商户"的全部实现**，无需改代码。

## 13. Nginx 反向代理配置（生产环境）

> 适用场景：生产环境 `npm run build:prod` 之后，前端静态文件 + 后端 jar + 上传图片三者
> 都要经过 Nginx 暴露到公网。配置错误会导致门店 logo、用户头像、推客二维码等所有
> `/profile/**` 资源 404。

### 13.1 最简配置（推荐）

```nginx
server {
    listen 80;
    server_name wetangou.example.com;

    # 前端静态资源（npm run build:prod 产物）
    location / {
        root /opt/wetangou/dist;
        try_files $uri $uri/ /index.html;
    }

    # 关键：/profile 静态资源代理到后端 jar（后端 ResourcesConfig 已映射到磁盘）
    # 不配这一行会导致门店 logo / 头像 / 二维码全部 404
    location /profile/ {
        proxy_pass http://127.0.0.1:8080;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
    }

    # 后端 API（前后端分离项目通用做法）
    location /dev-api/ {
        rewrite ^/dev-api/(.*)$ /$1 break;
        proxy_pass http://127.0.0.1:8080;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
    }
}
```

### 13.2 自检

```bash
# 1. 前端页能打开
curl -I http://localhost/
# 期望: 200 OK

# 2. 后端 API 能调
curl -I http://localhost/dev-api/captchaImage
# 期望: 200 OK

# 3. 上传图片能访问（关键）
curl -I http://localhost/profile/upload/demo/banner1.jpg
# 期望: 200 OK（如果存在）或 404（如果没文件）

# 4. 直接访问后端 8080 应该被防火墙拦
curl -I http://localhost:8080/
# 期望: connection refused 或被防火墙拒
```

### 13.3 dev 环境的 vue.config.js 代理

> 本地开发时前端跑 80 端口，后端跑 8080 端口，浏览器加载 `<img src="/profile/x.jpg">`
> 默认走 80 端口拿不到。`ruoyi-ui/vue.config.js` 已配 `/profile` 代理到 8080：

```js
'^/profile/(.*)': {
  target: baseUrl,  // http://localhost:8080
  changeOrigin: true
}
```

如果新增图片字段（比如新增 `biz_xxx.logo`），无需额外配置，规则自动覆盖。
