## §1 ApiPingController · 保留

### 1.1 实地证据
- 路径：`ruoyi-admin/src/main/java/com/ruoyi/web/api/ApiPingController.java`
- 代码注释：「健康检查端点。小程序启动时用这个端点替代 /captchaImage 探测后端可达性。/captchaImage 需要图片渲染，0.1s 起步；/api/ping 直接返 200，更轻量。微信真机通过 LAN 访问电脑时，IP 可能换，这个端点能秒级判断。」
- 调用方：`grep -rn "/api/ping" miniprogram7/` → 0 命中（mini 端实际未接入，但 controller 注释明确说"待用"）
- 风险评估：删除后 mini 启动可能要重新写 health check 调用方，得不偿失
- 决策：**保留**

### 1.2 改进建议（非本轮）
- 短期：在 mini 启动时接入 `wx.request({url: 'http://localhost:8080/api/ping'})` 真正使用起来
- 中期：加 `/api/health/ready` 和 `/api/health/live` 区分进程级和应用级 health check

## §2 miniprogram7/tests/ · 保留

### 2.1 实地证据
- 路径：`miniprogram7/tests/`
  - `util.test.js` (19 tests) — Haversine 距离、formatDistance、formatMoney、getNextDays 等纯函数
  - `request.test.js` (6 tests) — HTTP 请求工具
  - `pickNearestStore.test.js` (5 tests) — 选最近门店
- 配置：`miniprogram7/package.json` 含 `"test": "vitest run"`, `"test:watch": "vitest"`, `"vitest": "^2.1.0"`
- 运行结果：**30/30 PASS** (`npm test --prefix miniprogram7`)

### 2.2 风险评估
- 删除 30 个单测 = 0 测试保护
- 距离计算 / 门店选择 / 资金格式化等是核心算法，无测试 → 改这块易回归
- 决策：**保留**
