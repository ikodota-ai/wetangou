## 0. 这次改了什么（影响面）

| 层 | 改了什么 | 要不要额外操作 |

| 后端 | 商品校验语义、商家端新端点 `/api/product/merchant/list` | 换 jar |

## 1. 数据库（先做，且只做一次）

```bash
# 1) 备份（必须，本轮有 alter table）
mysqldump -h rm-xxx.mysql.rds.aliyuncs.com -u rds_root -p \
  --single-transaction --set-gtid-purged=OFF \
  bx_wetuangou biz_product biz_product_ext sys_menu sys_role_menu \
  > /data/backup/before_v4_$(date +%F_%H%M).sql

# 2) 执行（幂等，重复跑无副作用）
mysql -h rm-xxx.mysql.rds.aliyuncs.com -u rds_root -p bx_wetuangou \
  < sql/biz_product_field_gap_v4.sql
```

脚本做 5 件事：
1. 建 `biz_sale_channel` + 5 行渠道种子
2. `biz_product_ext` 加 9 列（用存储过程逐列判存在，跑完自动 drop）
3. 存量 `biz_product_ext` 补默认渠道；没有 ext 行的商品补插一行
4. 挂「投放渠道」菜单 + 5 个 `biz:saleChannel:*` 权限
5. 授权给 role_id=1（平台管理员）

### 验证

```sql
-- 期望 channels=5, ext_cols=25
select (select count(*) from biz_sale_channel) as channels,
       (select count(*) from information_schema.columns
         where table_schema='bx_wetuangou' and table_name='biz_product_ext') as ext_cols;

-- 期望 0（存量商品都该有渠道，否则小程序建品页默认勾选会是空的）
select count(*) from biz_product_ext where sale_channels is null or sale_channels='';

-- 期望 5 行权限
select perms from sys_menu where perms like 'biz:saleChannel:%';
```

> **为什么加列放 ext 不放主表**：`biz_product` 已经因为 `price`/`stock`/
> `validity_days`/`max_per_order` 这些 DEFAULT 架空了 null 校验，
> `ProductValidator` 不得不用「填了 0 等于没填」特判。再往主表塞 9 个带
> DEFAULT 的列只会把坑挖深。

启动约 100~200 秒（RDS 首连较慢）。

### 验证（**必须在 SQL 跑完之后**）

```bash
BASE=https://daodian.lanaoboxiang.com

# a) 活着
curl -s $BASE/api/ping                          # {"msg":"pong","code":200}

# b) 渠道字典（小程序和后台建品页都读这个，空了建品页投放渠道就是空弹窗）
curl -s $BASE/biz/saleChannel/enabled | head -c 300
# 期望：data 有 5 条，每条含 channelGroup 和 channelDesc，
#      顶层 defaultCodes = MINI_HOME,MINI_STORE,DISTRIBUTOR,GROUP_SHARE

# c) 商家端新端点存在（这次新加的，旧 jar 会 404）
curl -s -o /dev/null -w '%{http_code}\n' "$BASE/api/product/merchant/list?pageNum=1&pageSize=1"
# 期望 200（body 里 code=401 未登录），不是 404
```

如果 b) 返空数组 → SQL 没跑或跑错库。
如果 c) 返 404 → jar 没换成功。

## 5. 回滚

三层各自独立，可单独回滚：

```bash
# 后端
cd /data/wwwroot/daodian && mv ruoyi-admin.jar.bak ruoyi-admin.jar && 重启

# 后台前端
cd /data/wwwroot/daodian && rm -rf dist && mv dist.bak.<时间戳> dist

# 小程序
微信后台 → 版本管理 → 回退到上一个线上版本
```

**数据库不用回滚**：本轮 SQL 只加表/加列/加菜单，没改也没删任何存量数据。
旧版 jar 配新库能正常跑（多出来的列它不认，忽略即可）。

唯一要注意：如果只回滚后端但不回滚小程序，商家端列表页会因为
`/api/product/merchant/list` 404 而空白 —— 所以**回滚也要按「小程序先退、
后端后退」的反向顺序**，或者两个一起。
