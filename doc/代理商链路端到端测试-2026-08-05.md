## 发现并修复的问题

### Bug 1：SysUser 租户字段 @JsonIgnore 阻断 API
**现象**：admin 调用 `/system/user` 创建代理商账号时，**任何角色为 agent/merchant 的账号创建都失败**。
**根因**：`SysUser.tenantUserType/tenantAgentId/tenantMerchantId` 3 个字段都加了 `@JsonIgnore`，导致前端表单传的 `tenantUserType=1 + tenantAgentId=xxx` 永远到不了后端，syncMerchantUser 拿不到 ID 就拒绝。
**修复**：改为 `@JsonProperty(access = JsonProperty.Access.WRITE_ONLY)`，允许写入但不在响应中返回。
**文件**：`ruoyi-common/src/main/java/com/ruoyi/common/core/domain/entity/SysUser.java:30,33,36`

### Bug 2：admin 创建账号时 syncMerchantUser 强校验
**现象**：admin 不显式传 `tenantUserType` 时（普通员工账号），syncMerchantUser 按 role 推断出 userType=agent/merchant 但 ID 缺失 → 拒绝。
**根因**：`syncMerchantUser` 一刀切校验，admin 角色可能想建"纯系统用户"（无租户身份）。
**修复**：按角色推断时如缺 ID，自动降级为 `userType='0'`（平台/未绑定）；只有显式传 `tenantUserType` 才强校验。
**文件**：`ruoyi-system/src/main/java/com/ruoyi/system/service/impl/SysUserServiceImpl.java:367-388`

### Bug 3：agent 角色只绑了 list 权限
**现象**：agent 看自己代理商详情 / 查名下商户订单等所有业务接口都 403。
**根因**：`sys_role_menu` 之前只绑 6 个 `biz:agent:list` / `biz:merchant:list` 等，缺 query/add/edit/remove/export 和订单/商品/会员/门店的全部。
**修复**：补绑 50 个菜单权限，让 agent 能：
- 看/管名下商户所有业务（订单/商品/会员/账单/预约/分销/优惠券/佣金/规则/账户/记录/提现/协议/相册/员工）
- 增删改门店（AGENTS.md 业务要求）
- 完整管理自己代理商（增删改查导出）
**SQL 脚本**：`sql/biz_agent_role_permissions.sql`

## 后续待办（未在本轮处理）

1. **业务表缺租户过滤**：OrderServiceImpl/ProductServiceImpl/MemberServiceImpl 等没接 TenantContext，platform 角色能看所有商户数据（这是设计），但 agent 角色就算有权限也是看全部（无 merchant_id 过滤）。**风险**：跨商户数据泄漏。
2. **CategoryServiceImpl 等缺 merchant_id 过滤**：测试发现 biz/category/list 查到 3 条（跨商户的）。
3. **代理商没有 union id 概念**：同一用户在不同 agent 名下是不同 member（手机号相同 openid 不同即可），已在数据库模型上正确。
