# Wetangou 不同身份权限与菜单评估

> 评审日期：2026-08-02
> 评估对象：平台 / 代理商 / 商户 三类账号登录后看到的菜单、按钮、API 权限
> 评估方法：读 `sql/biz_tenant_menu.sql` §6 + `PermissionService.hasPermi` + `MerchantServiceImpl.checkMerchantDataScope` + 前端 `v-hasPermi` 校验

## 1. 身份与角色模型

### 1.1 三类身份

| 身份 | 业务标识 | 来源 | userType | 默认角色 role_key |
|---|---|---|---|---|
| **平台** | admin / 平台运营人员 | `sys_user` 直接登录 | `'0'` | 超级管理员 `admin` / 平台管理员 `platform` |
| **代理商** | 缴费后开通的代理商账号 | `sys_user` + `biz_merchant_user.userType='1'` | `'1'` | 代理商 `agent` |
| **商户** | 代理商开单产生的商户账号 | `sys_user` + `biz_merchant_user.userType='2'` | `'2'` | 商户管理员 `merchant` |

### 1.2 身份如何被识别

```
登录 → JwtAuthenticationTokenFilter 还原 LoginUser
     → SysLoginController.getInfo 透出 tenantContext（含 userType/agentId/merchantId）
     → 前端 vuex SET_USER_TYPE/SET_AGENT_ID/SET_MERCHANT_ID
     → resolveEntryPath() 按 userType 路由分流：
        '0' → /index         平台
        '1' → /agent/index   代理商
        '2' → /merchant/index 商户
```

### 1.3 租户上下文（业务数据隔离）

```
请求进入 → TenantContextHolder.set(LoginUser.tenantContext)
SQL 执行 → TenantSqlInterceptor 自动追加 WHERE merchant_id ...
退出    → TenantContextHolder.remove()
```

`LoginUser.tenantContext` 由 `TenantServiceImpl.buildContextByUserId(userId)` 构造：
- `biz_merchant_user` 中**未登记**的账号（如初始 admin）→ 兜底为平台（userType=0）
- 代理商 → `TenantContext.ofAgent(agentId, getMerchantIdsByAgentId(agentId))`
- 商户 → `TenantContext.ofMerchant(merchantId)`

## 3. 合理性与问题评估

### 3.1 总评分：**B+（86/100）**

| 维度 | 评分 | 备注 |
|---|---|---|
| 三身份路由分流 | A | login.vue 已按 userType 跳到对应工作台入口 |
| 菜单分层 | A- | 平台/代理商/商户三角色菜单清晰、不串 |
| 数据隔离 | A- | 三层防护（菜单 + interceptor + 写覆盖） |
| 按钮级权限 | A | 29 个 controller 全部 `@PreAuthorize` |
| 代理商工作台完整性 | D | 三个按钮全是占位（详见问题 2） |
| 商户账号创建流程 | C | 新增 SysUser 没同步建 biz_merchant_user（详见问题 3） |
| 商户工作台完整性 | D | 同上问题 2 |
| 默认角色无平台运营 | B | `platform` 角色建了但没绑默认账号（详见问题 4） |

### 3.2 关键优点

**1) 三层防护体系**
- **菜单层**：`sys_role_menu` 限定可见菜单
- **接口层**：29 个 controller 全部 `@PreAuthorize("@ss.hasPermi('xxx')")`
- **数据层**：`TenantSqlInterceptor` 拦截所有 biz_* SQL 自动加 `merchant_id` 条件
- **写侧层**：`TenantInsertInterceptor` 强制覆盖 merchantId 防伪造

**2) 关键数据可见性合理**
- 代理商看不到其他代理商的客户（`merchant_id IN (名下商户)`）
- 商户看不到其他商户的订单
- 商户看不到平台级支付凭证（防止 1 个商户拿到另 1 个商户的 mchId）
- 商户看不到代理商管理 / 商户管理（防止越权开单）

**3) 状态机保护**
- 代理商不能审核自己的缴费（`biz:agentfee:audit` 不授）
- 代理商不能删除商户（`biz:merchant:remove` 不授）
- 商户不能改平台参数

**4) 登录入口按身份分流**
- `resolveEntryPath()` 已实现，按 `userType` 跳 `/index` / `/agent/index` / `/merchant/index`
- 路由层 `/agent/index` 和 `/merchant/index` 已建好

### 3.3 问题清单

#### 问题 1：登录入口路由时序隐患（已实现但有 race）⚠️ 中

**位置**：`ruoyi-ui/src/views/login.vue:148-180`

**现状**：
```javascript
handleLogin() {
  this.$store.dispatch("Login", this.loginForm).then(() => {
    return this.$store.dispatch("GetInfo")          // ← 异步拿 userType
  }).then(() => {
    this.$router.push({ path: this.resolveEntryPath() })  // ← 在 then 内调用 ✅ 正确
  })
},
```

**评估**：当前实现**正确**——`resolveEntryPath()` 在 `GetInfo` 完成后调用，此时 `store.user.userType` 已 commit。

但 `resolveEntryPath()` 用了冗余的 `this.$store.state.user.userType` 防御性写法可读性差，建议改为：
```javascript
resolveEntryPath(userType) {
  if (userType === '1') return '/agent/index'
  if (userType === '2') return '/merchant/index'
  return '/index'
}
// 在 then 内：
const userType = this.$store.state.user.userType
this.$router.push(this.resolveEntryPath(userType))
```

**结论**：当前实现可用，但应加端到端测试覆盖 3 种身份（admin/agent/merchant）登录后的首跳路径。

#### 问题 3：新增 SysUser 没同步建 biz_merchant_user 🔴 高

**位置**：
- `ruoyi-admin/src/main/java/com/ruoyi/web/controller/system/SysUserController.java:121-144`（add）
- `ruoyi-system/src/main/java/com/ruoyi/system/service/impl/SysUserServiceImpl.java`（insertUserAuth 只插 sys_user_role）

**现状**：
管理员在「系统管理 → 用户管理 → 新增」创建代理商/商户账号时：
- ✅ 写入 `sys_user`
- ✅ 写入 `sys_user_role`（绑角色）
- ❌ **未**写入 `biz_merchant_user`（身份归属表）

**业务影响**：
- 该账号登录后 `TenantServiceImpl.buildContextByUserId` 查不到 `biz_merchant_user` 记录
- 兜底为**平台账号**（userType=0）
- 结果：**代理商登录后看到全平台数据，越权** 🚨
- 商户账号同病

**修复建议**（必修，0.5 天）：
- `SysUserController.add` / `edit` 时增加 `userType/agentId/merchantId` 三个字段
- `SysUserServiceImpl.insertUserAuth` 后同步写 `biz_merchant_user`：
  ```java
  if (userType != null) {
      MerchantUser mu = new MerchantUser();
      mu.setUserId(user.getUserId());
      mu.setUserType(userType);
      mu.setAgentId(agentId);
      mu.setMerchantId(merchantId);
      merchantUserMapper.insert(mu);
  }
  ```
- `edit` 时同步 update
- 「删除」时同步 delete

#### 问题 8：菜单与按钮权限字符串不一致 ⚠️ 中

**位置**：
- `sys_menu.perms` 定义：`biz:agent:query / add / edit / remove / export`（5 个）

### 3.4 业务矛盾点

#### 矛盾 1：代理商和商户都能看到「小程序代发布」✅ 合理
- 代理商给名下商户代发
- 商户自己发（自己 appid）
- 业务上都需要

#### 矛盾 2：代理商看不到「推客分销」❓ 值得讨论
- 代理商代发小程序时，佣金规则是按平台/商户配置的
- 代理商要不要看自己名下商户的佣金收入？

**当前实现**：代理商**看不到**「推客分销」任何菜单。

**实际影响**：
- 代理商对名下商户的「运营数据」无感知
- 业务上要不要给代理商「只看名下商户的佣金概览」？

**建议**（下一轮迭代）：
- 代理商工作台增加「佣金概览」卡：3 个数字（名下商户本月总佣金 / 已结算 / 待结算）
- 不需要看明细，但要一个总览

#### 矛盾 3：商户看不到「代理商管理 / 商户管理」✅ 合理
- 商户不应看到自己「付了多少钱给代理商」
- 但商户的服务到期时间、缴费记录是商户应看的

**当前实现**：
- 「商户收费」在租户管理目录下，**商户不可见**
- 商户看不到自己的缴费记录

**实际影响**：商户不知道下次续费时间。⚠️
