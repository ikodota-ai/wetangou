# E21 商品类型字典化 smoke + 字典字符集修复 · 2026-08-15

## 背景

8-14 计划里把「P1 字典化：admin 商品页 12 种下拉对接 biz_product_type 字典 API」列为待办。
本轮核查发现**前端 `loadTypeList` 早已实装**（`ruoyi-ui/src/views/biz/product/index.vue:424-432`）：
- `created()` 调 `loadTypeList`
- `loadTypeList` 调 `selectProductTypeList()`（productType.js 已存在）
- 下拉 v-for 渲染 `typeList`，typeText/loadTypeList 走动态

但后端 `/biz/productType/list` 返回的 typeName/typeDesc 是**乱码**（双重 UTF-8 编码），
前端下拉看上去像「å›¢è´­å¥—é¤\x90」之类的不可读文字，**等于没字典化**。

## 根因

v2 升级（8-14 13 commit）跑 `sql/biz_product_seed.sql` 时 MySQL 连接未指定 `utf8mb4`，
typeName/typeDesc 中文被按 latin1 二次编码落到 utf8mb4 列，存进去就是乱码。

## 修复

1. **`sql/biz_product_dict_charset_fix.sql`** — 22 行 UPDATE + `SET NAMES utf8mb4`，
   把 11 条字典的 typeName/typeDesc 直接覆盖为正确中文（可重复执行）
2. **smoke-e21.sh 21/21 PASS** — 端到端守门，确保任何回归都会立刻暴露

## 部署注意

所有升级到 v2 的环境（不只是本机 dev）都需要跑：
```bash
mysql -h<host> -uroot -p<pwd> --default-character-set=utf8mb4 ry-vue \
  < sql/biz_product_dict_charset_fix.sql
```
否则 admin 下拉和任何展示 typeName 的页面都会乱码。
