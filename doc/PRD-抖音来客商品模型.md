## 1. 文档目的与边界

### 1.1 为什么做这份文档
- 抖音来客是国内"商家创建团购/卡券"最成熟的参考实现，
  业务模型抽象度高，**品类 × 类型 × 步骤条 × 字段**四层抽象值得借鉴。
- 洞天团购当前 `biz_product` 字段是"团购套餐"一种类型的扁平化产物，
  已无法承载未来"代金券 / 次卡 / 储值卡 / 周期卡"等业务。
- 文档**不涉及抖音开放接口**，仅记录业务模型，作为内部 PRD 的参考。

### 1.2 不在本文档范围内
- 抖音开放平台对接 / 资质审核 / 抽佣结算
- 抖音 POI / 达人 / 直播 / 短视频带货
- 与微信生态对接的任何能力

### 1.3 适用范围
- 后端 `biz_product` 表结构演进
- 管理端「商品创建」表单
- 小程序端商品详情 / 下单 / 核销链路

## 2. 核心业务模型

### 2.1 两级抽象：**品类（Category）** + **类型（Type）**

| 概念 | 作用 | 决定 | 类比（洞天当前） |
| --- | --- | --- | --- |
| **品类** | 商家所处的行业（如餐饮、教培、丽人） | 保证金、行业资质、可选类型集合 | 完全没有 |
| **类型** | 商家卖什么形态（团购/代金券/次卡…） | 步骤条、字段集合、抽佣规则、核销逻辑 | `biz_product.product_type`（0/1/2，不全）|

**重要约束**：**类型受品类约束**。餐饮可选"团购套餐+代金券"，
教培可选"次卡+周期卡"，不同品类可选类型集合不同。

### 2.2 8 种商品类型（全量枚举）

| 类型 code | 名称 | 业务说明 | App 是否可创建 |
| --- | --- | --- | --- |
| `GROUPON` | 团购套餐 | 套餐商品，搭配自由，快速吸引顾客 | ✅ |
| `VOUCHER` | 代金券 | 现金抵扣券，出单快，便于引流增收 | ✅ |
| `TIMECARD` | 次卡 | 一次购买分次核销，增加用户粘性 | ✅ |
| `STORED_CARD` | 储值卡 | 通过存储金额，引导顾客多次到店消费 | ✅ |
| `PERIOD_CARD` | 周期卡 | 月/季/年卡等长周期商品，方便锁客 | ✅ |
| `HUIXIANG_CARD` | 惠享卡 | 大额分次核销，提前锁客 | ✅ |
| `PRESALE` | 预售券 | 先买后约，方便用户直播及短视频囤货 | ⚠️ 仅网页端 |
| `PICKUP_VOUCHER` | 提货券 | 支持多规格管理和门店库存设置 | ⚠️ 仅网页端 |

**特别注意**：`STORED_CARD / PERIOD_CARD / HUIXIANG_CARD` 需开通平台**「放心付」**保障服务才能创建。

### 2.3 组合券包（特殊类型）

`COMBO`：**跨类型子品混搭**，一次性购买，分次核销。
- 子品类型可任选：`GROUPON` / `VOUCHER` / `满减券` / `折扣券`（注：满减/折扣是**子品内嵌的**子类型，不是顶层 8 种之一）
- 售价 = 系统自动按子品价格累加（截图显示 99+8=107，**不等于**总价值 209）
- 总价值（划线价）= 用户视角的"原价"
- 步骤条含额外的「**商品资质**」步骤（其它类型无）

## 3. 步骤条模型

**核心结论**：**类型不同，步骤条不同**。

### 3.1 团购套餐 / 代金券（6 步）

1. 基础信息（品类、类型）
2. 商家信息（名称、收款方式、适用门店）
3. 商品信息（名称、价格、搭配/面值、头图、环境图、补充说明）
4. 售卖信息（投放渠道、职人带货、库存、售卖日期）
5. 交易规则（可消费日期、不可消费日期、每日时段、限购、售后、预约、券码类型）
6. 消费规则（店内其他优惠、额外费用、张数/人数限制、其他说明、平台统一说明）

### 3.2 组合券包（5 步，多了「商品资质」）

1. 基础信息
2. **商品信息**（含头图/辅助图/环境图，**子品代金券配置**）
3. **商品资质**（营业执照、行业许可证等）
4. 售卖信息
5. 交易规则
6. 消费规则（推断）

### 3.3 通用卡（次卡/储值卡/周期卡/惠享卡）

> 截图未覆盖此 4 类的步骤条，推断**与团购套餐类似但有「放心付」资质步骤**。

## 4. 字段模型（按类型分组）

### 4.1 通用字段（**所有类型都有**）

| 字段 | 必填 | 类型 | 约束/默认值 | 说明 |
| --- | --- | --- | --- | --- |
| 商品名称 | 是 | string | **40/60 字**（见下方） | 不得含错别字及特殊符号，需与内容一致 |
| 适用门店 | 是 | int[] | ≥1 | 多选，跨门店必选 ≥2 |
| 收款方式 | 不可编辑 | enum | `HEADQUARTERS` / `STORE` | 总部统一收款 / 门店独立收款 |
| 投放渠道 | 是 | enum | `UNLIMITED` / `LIMITED` | 不限制 / 限定 |
| 职人/店员带货 | 是 | bool | `true`/`false` | 允许/不允许 |
| 商品售卖日期 | 是 | date_range | `UNLIMITED` 或 起~止 | 到期自动延期 30 天 |
| 顾客可消费日期 | 是 | date_rule | 自购买次日起 N 天（默认 360），当天默认可用 | |
| 顾客不可消费日期 | 否 | date[] | 黑名单 | 默认全可 |
| 每日消费时段 | 是 | time_range[] | 全天可用 / 限定 | |
| 限购规则 | 否 | int | 不限制 / N 件 | |
| 售后政策 | 是 | text | | |
| 预约规则 | 否 | enum | `NONE` / `REQUIRED` / `WORKDAY_ONLY` | 无需预约 / 必预约 / 仅工作日可预约 |
| 券码类型 | 是 | enum | `PLATFORM` / `THIRD_PARTY` / `MERCHANT_OWN` | 抖音券/第三方券/商家自有码 |
| 店内其他优惠 | 否 | enum | `MUTEX` / `COEXIST` | 不与店内优惠同享 / 可同享 |
| 额外费用 | 否 | text | | |
| 使用张数限制 | 开关 | bool+int | 开启后必填单次最多 X 张 | |
| 使用人数限制 | 开关 | bool+int | **仅团购套餐**有 | |
| 其他说明信息 | 否 | text | **500 字**，禁止"美团/点评/最终解释权"字样 | |
| 平台统一说明 | 不可编辑 | text | 系统按品类/法规自动追加 | |
| 商品头图 | 是 | image[] | 见各类型说明 | |
| 环境图 | 否 | image[] | **最多 10 张** | |
| 项目补充说明 | 否 | text | | |

### 4.3 子品（搭配）字段模型

适用类型：`GROUPON`（必填）/ `COMBO`（必填）

```
商品组 1（可多组）
  ├── 组名（如"体恤"，可空）
  ├── 单品 1（可多个）
  │     ├── 名称（必填，例"连衣裙裤子套装衬衣T恤"）
  │     ├── 数量（必填，默认 1 份）
  │     └── 单价（必填）
  ├── 单品 2
  └── N选M（如"1选1"、"2选2"）
```

**N 选 M 业务说明**：消费者在 N 个单品中任选 M 个核销，
  商家可借此做"灵活套餐"。

### 4.4 单品快速录入

支持 3 种录入方式：
- **复用已有项目**：从历史单品库搜索+复用
- **上传规格参数图片**：OCR + AI 智能识别
- **拍摄外包装**：相机+AI 智能识别

（后两种需 OCR / 计算机视觉能力，洞天短期内可仅实现复用）

## 5. 抽佣规则（重要）

**抖音端按渠道抽佣**，截图示例：

> 您发布的团购套餐商品，**抖音省端 5%，豆包端 5%，抖音端 5%**

**洞天视角**：
- 抽佣渠道 = 平台分销渠道（自有 / 推客 / 第三方）
- 每种渠道独立配置费率
- 抽佣在结算时由后端按订单所属渠道计算

## 6. 品类（Category）模型

### 6.1 3 级层级

```
购物（顶级）
  └── 服饰鞋帽（二级）
        ├── 服装（三级）
        ├── 箱包（三级）
        ├── 鞋靴（三级）
        └── 内衣袜子（三级）
  └── 母婴用品（二级）
        └── 儿童服饰（三级）
```

### 6.2 品类字段（推断）

| 字段 | 含义 |
| --- | --- |
| `category_id` | 主键 |
| `parent_id` | 父级 ID，顶级为 0 |
| `name` | 当前级名称 |
| `level` | 1/2/3 |
| `industry_code` | 行业编码（决定保证金、资质） |
| `deposit_amount` | 行业保证金（分） |
| `allowed_types` | 该品类下可选商品类型集合 |
| `license_required` | 必填资质列表（如食品经营许可证） |
| `compliance_notice` | 平台统一说明模板 |
| `sort` | 排序 |
| `status` | 0启用/1停用 |

### 6.3 智能推荐

抖音来客在品类选择弹窗有「**智能推荐**」功能：

> 智能推荐以下品类 → 购物·服饰鞋帽·服装 / 购物·母婴用品·儿童服饰…

依据：历史创建品类 + 行业搜索热度。

## 7. 安心服务 / 放心付

**业务定位**：平台对消费者的资金保障服务。

| 概念 | 含义 |
| --- | --- |
| 安心服务 | 商家服务市场，集成各种增值服务 |
| 放心付 | 资金担保服务，类似支付宝担保交易 |
| 必须开通放心付的类型 | 储值卡 / 周期卡 / 惠享卡（**先收钱后服务**） |
| 未开通影响 | "暂不可创建此类商品" |

**洞天视角**：
- 我们是私域平台，资金由商家自有账户收取，不需要第三方担保
- 但**次卡/储值卡/周期卡仍需"冷静期"机制**（如 7 天无理由退款）
- 对应 `biz_commission_settle_job.sql` 已有"佣金冷静期"思路，可复用

## 8. 商家工作台（创建之外的辅助能力）

| 能力 | 说明 |
| --- | --- |
| **上品教程** | 顶栏"上品教程"入口（视频/图文教程）|
| **使用模板建品** | 根据所选品类推荐相似商品的模板，"AI 解读"+"成都市 3 万+人在搜" |
| **AI 智能助手** | 全程浮窗（小女孩头像），可唤起问答 |
| **历史记录建议** | 输入名称时弹出历史输入建议 |
| **预览** | 创建前模拟用户侧的商品详情页 |
| **提交审核** | 平台审核（抖音来客有审核流）|

**洞天视角**：
- "上品教程" = 商品创建帮助页（运营位）
- "使用模板建品" = 商品模板库
- "AI 智能助手" = 暂不需要（成本高）
- "预览" = **必须有**（创建后预览）
- "提交审核" = 暂不需要（自营商家）

## 9. 关键交互细节

### 9.1 智能推荐品类（弹窗）

- 顶部"智能推荐以下品类"
- 列表每项：`购物·服饰鞋帽·服装`（中间用·分隔）
- 底部"以上没有合适的品类，**查看全部品类**" 兜底
- "确认" 按钮（未选择时灰色）

### 9.2 类型选择（弹窗）

- 每种类型有 radio + 标题 + 副标题说明
- 副标题承担**教育用户**作用（例："套餐商品，搭配自由，快速吸引顾客"）
- 次卡有"详情"链接 → 介绍新功能（蓝条提示）
- 末尾 2 种（预售券/提货券）灰显 + "暂不支持在抖音来客 App 创建，请前往抖音来客网页端进行操作"

### 9.3 必填标识

- 红色 `*` 标识必填
- 红色 "请输入" / "请设置金额" 提示
- 字段失去焦点时实时校验

### 9.4 步骤条

- 横向 scroll tab，5-6 个 tab
- 当前步骤下划线加粗
- 不可跳步（必须按顺序）

## 11. 借鉴到洞天的落地路线（推荐）

### 11.1 立即做（P1）
- 建 `biz_product_category` 表（3 级，行业 + 保证金 + 可选类型）
- 建 `biz_product_type` 表（8 种）
- 改造 `biz_product` 关联 `category_id` + `type_id`
- 抽佣规则按渠道

### 11.2 短期做（P2）
- 5-6 步创建步骤条（按类型动态渲染）
- 商品搭配 + N 选 M
- 通用规则字段补全
- 消费规则字段

### 11.3 长期做（P3）
- 组合券包（子品累加）
- 平台统一说明
- 安心服务/放心付等价机制
- AI 助手/拍照识别
- 模板库
- 上品教程
