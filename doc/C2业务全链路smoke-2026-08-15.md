# C2 业务全链路 smoke · 2026-08-15

> **范围**：在 E11~E19 越权防护基础上，补 C2 业务全链路 E2E smoke（会员→下单→预支付→核销）
> **方法**：bash + curl + python json 解析；依赖现成 product 1000 (mid=1) + staff001 (store 200)
> **结论**：**7/7 PASS**；13/13 smoke + 10/10 JUnit + 30/30 vitest 三重全 PASS

## §0 TL;DR

| 步骤 | 端点 | DB 状态变化 | 验证点 |
|---|---|---|---|
| A. 会员登录 | `POST /api/auth/login` (mock code) | biz_member 新行 (memberId=9992xx) | token 长度 > 50 |
| B. 下单 | `POST /api/order` (productId=1000, num=1) | biz_order status=0 (待付款) | orderId 返 |
| C. 预支付 | `POST /api/order/prepay/{id}` (mock) | biz_order status=1, verify_code 生成, pay_time 设 | `mock=true` in resp |
| D. 门店核销 | `POST /api/order/verify` (staff, verifyCode) | biz_order status=2, verify_time, verify_user=store:7 | 200 + DB 状态变更 |
| E. 无鉴权 | `POST /api/order` (无 token) | 无变化 | resp code=401 |

## §1 链路详图
```
member (mock login) → 下单 (status=0)
                    → 预支付 mock (status=1, 生成 verifyCode)
                    → staff 核销 (status=2, verify_time, verify_user)
```

## §2 commission 链路
- `paySuccess` 内部调 `commissionService.settleForOrder(order)`
- 当 member 关联 distributor 时 commission 入账 (rate 10%, settle_days 7)
- C2 测试 member (9992xx) 无 distributor 关联 → commission 0 行（设计如此，不是 bug）
- 后续 C3 smoke 可加 distributor 关联 → 验证 commission 真实入账

## §3 业务关键点
- **prepay 内部已调 paySuccess**（mock 模式）：所以 `_e2e_paySuccess/{id}` 端点对 prepay 已 status=1 的订单返 500 是正常的
- **核销 verifyUser="store:7"** 格式：`<userType>:<userId>` (store=门店员工)
- **mock 模式**：`wx.miniapp.mockEnabled=true` (per appid) — e10 走的 appid=wx9e147c4e2151b123 开了 mock
- **AjaxResult 全用 HTTP 200**：业务错误通过 body.code=500 表达，不要依赖 HTTP 状态码判断
