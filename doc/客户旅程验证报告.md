## 本轮（2026-08-04）端到端验证发现并修复的真实 bug

| # | 位置 | bug | 修复 |
|---|---|---|---|
| 1 | `CommissionMapper.xml` | 根元素关闭后还有 select/update | 把后续 SQL 移到 mapper 内、删冗余 `</mapper>` |
| 2 | `DistributorMapper.xml` | 同款 bug | 同上 |
| 3 | `WxMaService.code2Session` | mock 条件过严（要求 appId 为空） | 改成 `isMockEnabled(merchantId)` 即可 |
| 4 | `ApiAuthController.login` | 已存在会员 update 路径**没写 inviteBy** | 补 inviteBy 回写（仅当原值空时） |
| 5 | `ApiOrderService.placeOrder` | 用通用 selectDistributorList 报 "Column merchant_id ambiguous" | 加 `DistributorMapper.selectDistributorByMemberId` 精准查 |
| 6 | DB `biz_commission` | 缺 `settled_to_distributor` 列 | 跑 `sql/biz_commission_settle_link.sql` 补列 |
| 7 | `WxMaService.getWxaCodeUnlimited` | 太阳码 mock 条件同样过严 | 同 #3 修复 |
| 8 | `sys_job` 表 | 缺 `settle_commission_task` 调度 | 跑 `sql/biz_commission_settle_job.sql` 插入 job_id=4 |
| 9 | `SettleCommissionTask` | 用 `Date before` 跟 SQL 内部 NOW 差 50ms 导致 linkSettlementToDistributor 找不到记录 | 两阶段用同一 now |
| 10 | `CommissionMapper.selectSettleGroupsByTime` | `settle_time = ?` DateTime 精度问题 | 改用 `settle_time >= ? AND < now+2s` range |

## 已知边界 / 待 production 化

- **真实微信支付回调**：测试环境无 mchId/apiV3Key/appId，prepay 报"凭证未配置"（生产部署前在「商户管理→微信配置」配置）
- **Redis 缓存**：merchant / sys_config / member 缓存 5 分钟生效，DB 配置改动后需清缓存或重启
- **员工工作台"今日预约"列表**：只显示当天，未来 N 天预约需另开接口
- **commission 真实入账**：依赖真实微信支付回调；测试期间通过 SQL 模拟验证 paySuccess 等价 SQL
