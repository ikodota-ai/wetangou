## 旅程 3：被邀请+省钱 ✅ 端到端实测通过

| 步骤 | 端点 | 实测结果 |
|---|---|---|
| 邀请人登录 (推客) | `POST /api/auth/login {code:inviter}` | ✅ memberId=1000 |
| 被邀请人登录 (带 inviteBy) | `POST /api/auth/login {code:invitee,inviteBy:1000}` | ✅ memberId=1001 |
| profile.inviteBy | `GET /api/member/profile` | ✅ inviteBy=1000, inviteTime=2026-08-04 07:14:29 |
| 下单自动归属 | `POST /api/order` | ✅ distributorId=1003（无需前端传） |
| 推客粉丝列表 | `GET /api/distributor/fans` | ✅ 1 个粉丝（memberId=1001） |

**实测证据**：
```sql
mysql> select order_id, member_id, distributor_id from biz_order where order_id=100015;
order_id: 100015, member_id: 1001, distributor_id: 1003 ✓
```

**本轮修补的真实 bug**：
- `ApiAuthController.login` 之前 update 路径**完全没写 inviteBy**，被邀请人登录后 invite_by 永远为空
- `ApiOrderService.placeOrder` 用通用 selectDistributorList 报 "Column merchant_id ambiguous"（member 表也含此列）
- `CommissionMapper.xml/DistributorMapper.xml` 根元素关闭后还跟着 `<select>/<update>`，MyBatis 启动失败
