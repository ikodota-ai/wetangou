# 菜单平铺重组（2026-08-05）

## 背景
之前菜单结构存在"团购运营"顶级目录，下挂 6 个二级模块（门店商品/交易订单/会员体系/推客分销/平台配置/租户管理）。
本轮按用户意见去掉这一层虚拟目录，6 个模块平铺为顶级，更直观；并把 agent 的"租户管理"改名为"我的商户"。

## 变更
- `sys_menu` 表
  - `menu_id=2001 团购运营` → 删除
  - `menu_id IN (2108,2109,2110,2111,2112,2215)` parent_id 改 0，平铺为顶级
  - `2215 租户管理` → `2215 我的商户`
  - order_num 5~10
- `sys_role_menu`
  - admin(1) / platform(3)：绑 6 个顶级
  - agent(4)：只绑 2215 我的商户
  - merchant(5)：绑 5 个（不含 2112 平台配置）
  - 清悬空绑定

## 验证
| 账号 | 顶级菜单 |
|------|----------|
| admin | 系统管理/系统监控/系统工具/门店商品/交易订单/会员体系/推客分销/平台配置/我的商户 |
| platform001 | 平台配置/我的商户 |
| agent001 | 我的商户 |
| merchant001 | 门店商品/交易订单/会员体系/推客分销/我的商户 |

- 后端：getRouters 接口返回结构正确（component=Layout, alwaysShow=true, children 完整）
- 前端：npm run build:prod 通过
- Redis：新菜单树生效（后经核实菜单不走缓存，当时的 flushdb 是多余动作，见 doc/部署上线指南.md §7.2）
