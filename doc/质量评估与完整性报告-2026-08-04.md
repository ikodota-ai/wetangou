## 2. 本轮真实发现并修复的 Bug（4 个 commission 入账链路）

### Bug 1：MySQL DATETIME 秒精度 vs Java Date 毫秒精度不匹配

**现象**：`settleExpiredCommissions` 写 `settle_time = ?`（毫秒 0.053s），MySQL DATETIME 列只存秒，写入 0.000s。下次 `linkSettlementToDistributor` 用原 `now`（毫秒 0.053s）范围查，**查不到刚写入的记录**。

**修复**：`DateUtils.truncateToSeconds(Date)` 把毫秒截断到秒，service 层 line 87 调用。

**测试**：
- commission 8 (create_time=8 天前) 写入后等 Quartz 任务
- 之前：rows=1 distributors=0（groups 查 0 行）
- 修复后：rows=1 distributors=1 ✅，frozen -3.80 / available +3.80 / total +3.80

### Bug 2：markSettledByTime 用 `=` 精确匹配漏记录

**现象**：和 Bug 1 同根因——`where settle_time = ?` 精确匹配毫秒值，写入的 0.000s 跟 0.053s 不等，影响 0 行。

**修复**：改成 `settle_time >= ? AND settle_time < date_add(?, interval 2 second)` 范围匹配。

**测试**：commission 8 settled_to_distributor 0→1 ✅

### Bug 3：incAvailableAmount 没同步 total_commission

**现象**：service 注释 "扣减 frozenAmount / 增加 availableAmount"，但 total_commission 漏维护，导致推客累计佣金为 0。

**修复**：mapper SQL 增加 `total_commission = ifnull(total_commission, 0) + #{delta}`。

**测试**：distributor 1003 total_commission 0→3.80→7.60（两次结算）✅

### Bug 4：truncateToSeconds 编译时找不到符号

**现象**：mvn compile 报 "找不到符号 truncateToSeconds"，但 DateUtils 顶部 import 已存在，m2 仓库 jar 也有该方法。

**原因**：DateUtils 继承自 `org.apache.commons.lang3.time.DateUtils`，后者有同名方法但签名不同（参数类型是 long/Date 不同）。编译器在父类中找到一个同名方法，**认为子类调用的是继承的方法**而非子类的 static 静态方法，导致解析冲突。

**修复**：用全限定名 `com.ruoyi.common.utils.DateUtils.truncateToSeconds(settleTime)` 强制解析。

**测试**：mvn 编译 BUILD SUCCESS。

### 4.2 菜单可见性

| 角色 | getRouters 菜单数 | 业务范围 | 评估 |

### 4.3 业务身份回填

**当前实现**（`TenantIdentityResolver.java:46`）：
- 登录时从 `biz_merchant_user` 反查 userType/agentId/merchantId

## 5. 模块间逻辑评估

### 5.1 完整链路验证（commission 真实入账）

```
下单 placeOrder
  → 创建 Order (status=0)
  → /api/order/_e2e_paySuccess
    → ApiOrderService.paySuccess
      → 改 Order.status=0→1, payTime, verifyCode
      → ApiCommissionService.settleForOrder
        → 查 commission_rule (rate=10%)
        → 写 biz_commission (status=0, frozen += amount)
        → distributor total_commission += amount
  → 等冷静期 7 天
  → SettleCommissionTask (Quartz 30s 周期, 生产改 0 0 3 * * ?)
    → settleExpiredCommissions: status=0→1, settle_time=now
    → linkSettlementToDistributor: frozen→available, markSettled
  → 推客申请提现 withdraw.apply
  → 后台审核 approveWithdraw / rejectWithdraw
  → 累计 withdraw_amount 字段
```

**实测数据**：
- commission 8: amount=3.80, status=0→1, settled=0→1, settle_time=21:46:30
- distributor 1003: frozen 3.80→0, available 12.80→16.60, total 3.80→7.60
- 全链路 5 步走通 ✅
