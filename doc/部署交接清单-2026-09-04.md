## 四之二、头像走对象存储（2026-09-04 追加，nginx 兜底存量数据）

### 改动说明
- `ApiMemberController.uploadAvatar` / `SysProfileController.avatar` / `CommonController.uploadFiles`
  三处原来用 `FileUploadUtils.upload()`（落本机磁盘）→ 改为 `uploadByStorage()`（走 OSS）。
- 根因：生产 nginx 只配了 `location / { try_files $uri $uri/ /index.html; }`，
  没有 `/profile/` 的 alias，于是 `GET /profile/avatar/xxx.jpg` 被兜底成首页（200 + text/html）。
  商品图早就走了 OSS（`CommonController.uploadFile`），头像漏改了。
- 新上传的头像返回 OSS 绝对地址（`https://wetuango.oss-cn-shenzhen.aliyuncs.com/avatar/...`），
  `toFullUrl` 对其直接放行，不再经过 nginx 反代。

### 存量数据（5 条 `/profile/avatar/...`）
这批头像文件在生产服务器 `/data/wwwroot/daodian/uploadPath/avatar/` 下物理存在，
但 nginx 没有路由能访问到。改好后新上传的头像走 OSS 不再受此限制，存量头像要显示
需在 nginx 加 `/profile/` 兜底。

**注意：后端本身能吐 `/profile/`**。`ResourcesConfig.addResourceHandlers` 里注册了
`/profile/**` → `file:${ruoyi.profile}/`，且 `SecurityConfig` 对 `GET /profile/**` 是 permitAll。
本地实测 `curl http://localhost:8080/profile/avatar/2026/08/22/xxx.jpg`
→ `200 image/jpeg 4843 bytes`，是**通的**。

所以生产打不开的唯一原因是 **nginx 从没把 `/profile/` 转发给后端**，
被 `location / { try_files $uri $uri/ /index.html; }` 当成前端路由吃掉了。
这也是为什么本地一直没复现。

**nginx 配置片段**（放在 `location / { try_files … }` **之前**）——
推荐 proxy_pass 而不是 alias，直接复用后端已有的 resource handler，
不用在 nginx 里再维护一份 uploadPath 路径（改了 `--ruoyi.profile` 不会两边不一致）：
```nginx
# 存量头像 / 旧上传文件：转给后端的 /profile/** 静态映射
location /profile/ {
    proxy_pass http://127.0.0.1:8083;
    proxy_set_header Host              $host;
    proxy_set_header X-Real-IP         $remote_addr;
    proxy_set_header X-Forwarded-For   $proxy_add_x_forwarded_for;
    proxy_set_header X-Forwarded-Proto $scheme;
    expires 7d;
}
```

### 服务器操作顺序
1. 停后端（`kill $(cat /data/wwwroot/daodian/ruoyi.pid)` 或 `ps -ef | grep java | grep -v grep | awk '{print $2}' | xargs kill`）
2. 上传新 `jar` + `dist`（dist 解压到 `www/admin/`，参考 start.sh）
3. 启动后端（`/opt/jdk17/bin/java -jar ...`，见 start.sh）
4. 验证：`curl -I https://daodian.lanaoboxiang.com/api/member/avatar`（POST 带 token + 图片）
5. 加 nginx /profile/ 兜底（可选，只为存量头像显示）
6. `nginx -t && nginx -s reload`
