## 1. 环境准备（两条路径都要做）

### 1.1 关掉 mock 登录 ⚠️ 最关键

当前 `sys_config` 里 `wx.miniapp.mockEnabled=true`，
`WxMaService.code2Session` 会**直接用 code 派生假 openid**（`mock_<code>`），
根本不请求微信服务器：

```java
// WxMaService.java:81
if (wxMaConfig.isMockEnabled(merchantId)) {
    mock.put("openid", "mock_" + jsCode);   // 假 openid
    return mock;
}
```

不关掉的后果：**你以为在验真机，其实验的还是 mock**，
拿到的 openid 是 `mock_xxx` 而不是真实微信 openid，
「同一微信免密切换」这个核心能力根本没被验证到。

**mock 开关有两层，商户级优先，两层都要改**（我实测踩过：只改 `sys_config` 无效）：

```java
// WxMaConfig.isMockEnabled(merchantId)
Merchant merchant = getMerchant(merchantId);
if (merchant != null && StringUtils.isNotEmpty(merchant.getMockEnabled())) {
    return "0".equals(merchant.getMockEnabled());   // 商户级优先，直接 return
}
return isMockEnabled();                             // 才轮到 sys_config
```

⚠️ **`biz_merchant.mock_enabled` 的语义是反的**：`'0'` = **开启** mock，`'1'` = 关闭。
当前商户 1 的值就是 `'0'`（开启中）。

```sql
-- ① 商户级（优先，必须改）：'1' = 关闭 mock
UPDATE biz_merchant SET mock_enabled = '1' WHERE merchant_id = 1;

-- ② 全局兜底
UPDATE sys_config SET config_value = 'false' WHERE config_key = 'wx.miniapp.mockEnabled';

-- ③ 核对：期望 mock_enabled=1
SELECT merchant_id, appid, mock_enabled FROM biz_merchant WHERE merchant_id = 1;
```

改完**必须清三个 Redis key**，否则改库完全不生效
（`getMerchantById` 把整个 Merchant 对象缓存在 Redis 里，我实测踩过：
只改库不清缓存，假 code 依然能登录成功）：

```bash
/opt/local/bin/redis-cli del sys_config:wx.miniapp.mockEnabled
/opt/local/bin/redis-cli del "merchant:id:1"
/opt/local/bin/redis-cli del "merchant:appid:wx9e147c4e2151b123"
```

### 1.1.1 自检：确认 mock 真的关了（强烈建议做）

用一个假 code 打一次 —— 走 mock 会**成功**，走真实微信会**失败**：

```bash
curl -s -X POST http://localhost:8080/api/merchant/staff/acceptInvite \
  -H 'Content-Type: application/json' \
  -d '{"code":"fake_probe","scene":"invite:1:100:<有效邀请码>","nickName":"probe"}'
```

| 返回 | 含义 |
|---|---|
| `{"msg":"微信登录失败：","code":500}` | ✅ mock 已关，走真实微信（**这是期望结果**） |
| `{"msg":"已提交入职申请..."，"code":200}` | ❌ mock 仍生效，回去清 Redis |

> ⚠️ 这个自检会**消耗掉一个邀请码**（走到 mock 成功分支时），
> 所以拿一个专门用来探测的码，别用你准备真机验证的那个。

> 另有一层保险：profile 含 `prod` / `aliyun-oss` 等生产语义时，
> `isProductionProfile()` 会**强制关闭 mock**，无视上面两个配置。
> 所以正式上线时不必担心 mock 被误开。

同时确认 appId / secret 是真实值（当前库里已配）：

```sql
SELECT config_key, config_value FROM sys_config WHERE config_key IN ('wx.miniapp.appId','wx.miniapp.secret');
-- 期望：wx9e147c4e2151b123 / 2e58986bb6c994c0e7a23e7bab24b218
```

> 验证结束后如果还要跑 smoke，要把两层都改回去（smoke 依赖 mock 造 openid）：
> ```sql
> UPDATE biz_merchant SET mock_enabled = '0' WHERE merchant_id = 1;   -- '0' = 开启
> UPDATE sys_config SET config_value = 'true' WHERE config_key = 'wx.miniapp.mockEnabled';
> ```
> 并再清一次 Redis。

### 1.2 修正 BASE_URL（IP 已变）

`miniprogram7/utils/config.js` 里写的是 `172.31.26.216`，
但当前机器 en0 是 **`172.20.10.2`**（看起来已从 WiFi 切到手机热点）。

不改的后果：真机上所有请求超时，卡在首页。

```bash
ifconfig en0 | grep 'inet ' | awk '{print $2}'   # 确认当前 IP
```

把 `config.js` 的 `resolveBaseUrlDefault()` 返回值和 `BASE_URL_FALLBACKS[0]`
都改成当前 IP。**手机和电脑必须在同一网络**（连同一 WiFi，或电脑连手机热点）。

自检 —— 用手机浏览器打开：

```

```

返回 JSON 才说明手机能访问到后端。打不开就是网络/防火墙问题，先解决这个。

## 2. 路径 A：发布前用开发者工具验业务闭环

### 2.1 生成邀请码

后台 → 门店商品 → 员工邀请 → 生成邀请码（商户 1 / 门店 100 / 角色 STAFF）
→ 点「二维码」→ 弹窗里能看到三步说明和 scene。

也可直接用库里现成的有效邀请码：

| 邀请码 | 门店 | 有效期 | scene | 建议用途 |
|---|---|---|---|---|
| `ZQESSC` | 100 | 2026-08-29 | `invite:1:100:ZQESSC` | 真机验证主用 |
| `FTR9BZ` | 100 | 2026-08-29 | `invite:1:100:FTR9BZ` | 1.1.1 自检探测用 |
| `NSXXLN` | 100 | 2026-08-29 | `invite:1:100:NSXXLN` | 备用 |

（截至 2026-08-22 23:35 实测这三个 `status=0` 可用；如已被用掉请在后台重新生成）

> 邀请码是**一次性**的（用掉后 `status=0→1`）。重复验证要重新生成。

### 2.2 模拟扫一扫直达

开发者工具 → 编译模式下拉 → 添加编译模式：

- 启动页面：`pages/merchant/scan/index`
- 启动参数：`scene=invite%3A1%3A100%3AZQESSC`

> scene 必须 **URL 编码**（`:` → `%3A`）—— 真实小程序码里就是编码过的，
> `onLoad` 里有 `decodeURIComponent`。不编码会解析失败。

**预期**：
1. 直接落到「加入商家」页，显示转圈 +「正在识别邀请码…」，**不闪现「扫描员工邀请码」按钮**
2. 弹确认框「加入该商家？」
3. 点「提交申请」→ 提示「申请已提交，请联系店长在后台审核通过」
4. 自动返回上一页

### 2.3 验待审核状态（此时不该能登录）

```sql
SELECT u.user_id, u.user_name, u.user_type, u.openid, u.openid_bound, s.status, s.merchant_id, s.store_id
FROM sys_user u JOIN biz_merchant_staff s ON s.user_id = u.user_id
WHERE s.merchant_id = 1 ORDER BY u.user_id DESC LIMIT 3;
```

必须满足（这几条对应已修的 P0 越权漏洞，重点看）：

| 字段 | 期望值 | 说明 |
|---|---|---|
| `s.status` | `3` | 待审核，不是 0 |
| `u.user_type` | `02` | **绝不能是 `00`** —— `00` 会被授予 PLATFORM 角色 |
| `u.openid` | 真实 openid（`o` 开头） | 若是 `mock_` 开头 → 1.1 没生效，回去关 mock |
| `u.openid_bound` | `1` | — |

小程序端此时点「我的 → 切换到商家版」，**必须提示等待审核、不能进工作台**。

### 2.4 店长审核

后台 → 员工邀请 → 待审核员工 → 找到该员工 → 审核通过。

```sql
-- 期望 status 变 0
SELECT id, user_id, status FROM biz_merchant_staff WHERE user_id = <上一步的 user_id>;
```

### 2.5 验免密登录 + 无越权

小程序 →「我的」→「切换到商家版」

**预期**：
- **不弹任何授权框**（靠 `wx.login()` 静默换 openid），直接进商家工作台
- 底部/首页显示门店名「洞天团购·旗舰店」

越权检查（关键）—— 开发者工具 Console：

```js
const t = wx.getStorageSync('staffToken')
wx.request({
  url: 'http://172.20.10.2:8080/api/platform/merchant/list?pageNum=1&pageSize=2',
  header: { Authorization: 'Bearer ' + t },
  success: r => console.log('平台端点应 403 →', r.data.code)
})
```

**期望 `403`**。如果返 `200`，说明店员拿到了平台权限（P0 越权回归了），立即停下报告。

### 2.6 验双 token 不互相踩

1. 商家版 →「返回会员端」→ 会员端功能正常（会员 token 还在）
2. 再「切换到商家版」→ **秒进、零请求**（用本地缓存 staffToken）
3. Console 确认两个 token 并存：

```js
console.log('member:', !!wx.getStorageSync('memberToken'),
            'staff:', !!wx.getStorageSync('staffToken'),
            'current:', wx.getStorageSync('currentIdentity'))
// 期望 member: true staff: true current: staff（或 member，取决于当前在哪端）
```

4. 退出登录 → 三个 key 应全部清空（`app.js logout` 已补清）

### 2.7 验异常路径

| 场景 | 操作 | 预期 |
|---|---|---|
| 邀请码已用 | 用 2.2 的同一个 scene 再编译一次 | 弹「邀请码已使用」 |
| 邀请码过期 | 用 `invite:1:100:F403187A`（已过期） | 弹「邀请码已过期」 |
| 门店不匹配 | 用 `invite:1:999:ZQESSC` | 弹「邀请码与门店不匹配」 |
| scene 格式错 | 用 `invite:1:100`（缺一段） | toast「段数不对」，**且退回手动扫码按钮态**（不卡在转圈） |
| 离职后 | 后台把该员工改离职，再切商家版 | 拒绝登录 |

> 最后一行「退回手动扫码按钮态」是这次改动新加的 —— 4 条失败路径都会复位
> `fromScene`，否则页面永久卡在「正在识别…」没有出路。

## 5. 排错

| 现象 | 原因 | 处理 |
|---|---|---|
| openid 是 `mock_xxx` | mock 未关（**多半是只改了 `sys_config`，漏了 `biz_merchant.mock_enabled`**）/ Redis 未清 | 见 1.1 |
| 请求全超时 | BASE_URL IP 不对 / 手机电脑不同网 | 见 1.2 |
| 「小程序未接入或已停用」 | appid 查不到对应商户 | 查 `biz_merchant.appid` |
| 落地页空白无反应 | scene 未 URL 编码 | `:` 要写成 `%3A` |
| 卡在「正在识别…」 | scene 解析失败且未复位 | 应已修，若复现请报告 |
| 提示「NOT_BOUND」(600) | 该微信没绑员工 | 正常，先扫码入职 |
| 提示 601 | 待审核 | 正常，让店长审核 |
| 平台端点返 200 | **P0 越权回归** | 立即停止并报告 |
