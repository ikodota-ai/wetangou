# G6 新会员自邀防御 · 2026-08-15

## 背景

`smoke-c6.sh`（扫码入会 + 自动归属 commission 链路）由前一轮 C6 链路发现一处潜在风险：
`ApiAuthController.login()` 的自邀检查 hook (`memberId0(openid)`) 是一段 **stub 死代码**，永远返回 `null`，
意味着 line 71 的 `if (inviteBy != null && inviteBy.equals(memberId0(openid)))` **永远不会触发**。

老会员路径 (`else` 分支，line 109) 的自邀防御 `!inviteBy.equals(member.getMemberId())` 是 OK 的，
但**新会员路径**（`if (member == null` 分支）没有任何自邀防御，仅靠 `isValidInviter(merchantId, inviteBy)`
做合法性校验（`selectMemberByOpenid` 在新会员场景下永远为 null，所以不会自拒）。

## 修复

`ruoyi-admin/src/main/java/com/ruoyi/web/api/ApiAuthController.java`:
- `memberId0(String openid)` → `memberId0(Long merchantId, String openid)`
- 实现改为：按 `(merchantId, openid)` 查 `Member`（多商户隔离）
- 已存在 → 返回 `memberId`（登录主流程据此在 line 71 清掉自邀）
- 不存在 → 返回 `null`（新会员场景，`inviteBy` 与未生成 memberId 不可能相等，line 71 降级为「保留外部传值」）
- 调用方 line 71 同步改为 `memberId0(merchantId, openid)`

## 防御矩阵

|---|---|---|---|---|
| 老会员首次登录 | 合法他人 | 合法他人 | ✅ | ✅ |

| 新会员 | 0/不存在 | null | ✅ | ✅ |
