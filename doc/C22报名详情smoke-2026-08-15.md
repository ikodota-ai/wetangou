## 真实业务缺陷 × 2 (已修)
**P1 脱敏缺陷**: `ApiBookingController.signupDetail` 用 LinkedHashMap 手工组装 VO,绕过 @Sensitive 序列化器
- `vo.put("phone", signup.getPhone()); // 明文` — 实际返 11 位明文 13800138002
- `vo.put("storePhone", signup.getStorePhone());` — 同样明文 13434123069

**根因**: BookingMember domain 已有 `@Sensitive(PHONE)`,但 signupDetail 不直接返 entity,而是手工 put,Jackson 序列化器不再触发。

**修复** (1 行 + 1 行 import):
```java
import com.ruoyi.common.enums.DesensitizedType;
vo.put("phone", DesensitizedType.PHONE.desensitizer().apply(signup.getPhone()));
vo.put("storePhone", DesensitizedType.PHONE.desensitizer().apply(signup.getStorePhone()));
```

**验证**: 修复后 phone=138****8002 storePhone=134****3069 (中间 4 位 \*)
