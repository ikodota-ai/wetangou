# 上线数据迁移方案（2026-08-22）

> 回答「能不能直接把本地库导到服务器」。
> 结论：**能跑通，但不建议整库直导**。推荐「结构走脚本 + 只搬配置数据」。

## 一、为什么不建议整库 dump

本地 `ry-vue` 实测体检（71 表 / 12.5MB）：

| 项 | 实测 | 问题 |
|---|---|---|
| `sys_user` 41 行 | **21 个账号密码是默认 `admin123`** | `staff_*` / `c44_*` / `*_c43` 等 30+ 测试账号，等于给生产开后门 |
| `biz_member` 888 行 | **878 个 mock openid**（`mock_*` / `freed_*` / `smoke_open_*`） | 真实微信用户只有 1 个 |
| `biz_order` 232 笔 | 全是 smoke 造的假单 | 污染报表 / 佣金结算 |
| `biz_product` 266 个 | 绝大多数 `SMOKE_*` | 商品库要重建 |
| `sys_job_log` | **42168 行** | 垃圾日志占了库的大头 |
| `wx.pay.notifyUrl` | `https://your-domain.com/...` | 占位值 |
| mock 开关 | 两个都 `true` | prod profile 会代码层兜住，但数据层也该改 false |
| 字符集 | `biz_product_category` 1 行双重编码、`sys_menu` 1 行菜单名乱码 | 导过去是永久脏数据 |
| 备份表 | `sys_menu_bak_*` / `sys_role_menu_bak_*` | 冗余 |

## 二、推荐方案：结构走脚本 + 搬配置数据

### 步骤 1：服务器建库 + 跑初始化脚本

```bash
mysql -uroot -p -e "CREATE DATABASE \`ry-vue\` DEFAULT CHARACTER SET utf8mb4 COLLATE utf8mb4_general_ci;"
DB_PASSWORD=生产密码 bash sql/deploy/init-all.sh ry-vue
mysql --default-character-set=utf8mb4 -uroot -p ry-vue < sql/deploy/sys_config_production.sql
```

这样得到的库：**表结构完整 + 261 个菜单 + 25 个业务页 + 11 种商品类型字典 + 96 个行业品类 + 4 个定时任务**，
且**没有一条测试数据**。已实测 `/getRouters` 正常、25 页菜单齐全。

### 步骤 2：如果你想把本地「配置类」数据带过去（可选）

只导这几张纯配置表，安全：

```bash
# 本地导出（注意 --default-character-set，否则中文变乱码）
/usr/local/mysql/bin/mysqldump --default-character-set=utf8mb4 \
  -uroot -p133301 --no-create-info --complete-insert --skip-triggers \
  ry-vue sys_dict_type sys_dict_data > /tmp/dict.sql

# 服务器导入
mysql --default-character-set=utf8mb4 -uroot -p ry-vue < /tmp/dict.sql
```

> `sys_menu` / `sys_role_menu` **不要**从本地导——`init-all.sh` 已经建全了，
> 而且本地那两张表有重复 perms 和 1 条乱码菜单名。

### 步骤 3：商户 / 门店 / 商品用后台页面录入

商品 266 个里几乎都是 smoke 数据，没有搬的价值。生产上：
1. 「租户管理 → 商户管理」建真实商户，填真 appid / AppSecret / 支付凭证
2. 「门店商品 → 门店管理」建门店
3. 「门店商品 → 商品管理」录真实商品

## 三、如果你坚持整库直导（快，但必须做清洗）

适用场景：**你想保留那 266 个商品和分类结构当模板**，愿意接受清洗成本。

```bash
# 1) 本地导出（排除垃圾表）
/usr/local/mysql/bin/mysqldump --default-character-set=utf8mb4 -uroot -p133301 \
  --single-transaction --routines --events \
  --ignore-table=ry-vue.sys_job_log \
  --ignore-table=ry-vue.sys_logininfor \
  --ignore-table=ry-vue.sys_oper_log \
  --ignore-table=ry-vue.sys_menu_bak_20260805_022842 \
  --ignore-table=ry-vue.sys_role_menu_bak_20260805_022842 \
  ry-vue > /tmp/ry-vue-full.sql

# 2) 传到服务器并导入
scp /tmp/ry-vue-full.sql 用户@服务器:/tmp/
mysql --default-character-set=utf8mb4 -uroot -p ry-vue < /tmp/ry-vue-full.sql
```

**导入后必须立刻执行清洗**（顺序别改）：

```sql
-- 1) 删测试账号（保留 admin，其余按需保留）
DELETE FROM sys_user WHERE user_name REGEXP '^(staff_|c44_|c4403|platform_c43|agent_c43|owner_c43|manager_c43|staff_c43|agent_c37)';
DELETE FROM sys_user WHERE user_name IN ('staff001','platform001','agent001','merchant001','agent002','ry');

-- 2) 剩下的账号强制改密（21 个还是 admin123）
--    改完让每个人首次登录自己改；或直接在后台「用户管理」重置
UPDATE sys_user SET password='<新的BCrypt哈希>' WHERE user_id <> 1;

-- 3) 清 mock 会员与假订单（有外键依赖的先删子表）
DELETE FROM biz_commission WHERE order_id IN (SELECT order_id FROM biz_order);
DELETE FROM biz_order;
DELETE FROM biz_member WHERE openid LIKE 'mock%' OR openid LIKE 'freed_%' OR openid LIKE 'smoke_open_%' OR openid LIKE '%probe%';

-- 4) 关 mock、清占位配置
UPDATE sys_config SET config_value='false' WHERE config_key IN ('wx.miniapp.mockEnabled','wx.pay.mockEnabled');
UPDATE sys_config SET config_value='https://你的域名/api/pay/notify' WHERE config_key='wx.pay.notifyUrl';
UPDATE biz_merchant SET mock_enabled='0';

-- 5) 修字符集损坏的那行
UPDATE biz_product_category SET category_name='美食', full_path='美食' WHERE category_id=10000;

-- 6) 兜底：parent_id 不能有 NULL，否则后台侧边栏 500
UPDATE sys_menu SET parent_id=0 WHERE parent_id IS NULL;
```

清洗完跑一次自检：

```bash
bash .github/scripts/preflight-prod.sh
```

## 四、两种方案对比

| | 结构走脚本（推荐） | 整库直导 |
|---|---|---|
| 干净度 | 零测试数据 | 需手工清洗，容易漏 |
| 耗时 | 脚本 6 秒 + 手工录商户/商品 | dump/导入 1 分钟 + 清洗 |
| 风险 | 低 | 漏删一个默认密码账号就是入口级漏洞 |
| 适合 | **正式上线** | 内部演示 / 压测环境 |

## 五、无论哪种方案，上线前都要做

1. `bash .github/scripts/preflight-prod.sh` → FAIL=0
2. 启动带 `prod`：`--spring.profiles.active=prod,druid,aliyun-oss`（漏了会走 mock 支付）
3. 小程序 `miniprogram7/utils/config.js` 的 `BASE_URL` 换成 HTTPS 域名
4. 微信后台「服务器域名」白名单加上该域名
5. 登录后台确认侧边栏「团购运营」下 6 个分组 25 个页面都在（验证菜单没缺）
