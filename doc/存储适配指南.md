# 分布式文件存储适配指南

> 一行配置切换 local / MinIO / 阿里云 OSS / 七牛 / 腾讯云 COS / AWS S3，
> 无需改任何业务代码。

## 架构

```
┌─────────────────────────────────────────────────────┐
│  业务代码（CommonController / ImageUpload 等）       │
│  调用 FileUploadUtils.uploadByStorage(file)          │
└────────────────────┬────────────────────────────────┘
                     ↓
        ┌────────────┴────────────┐
        ↓                         ↓
   application.yml         StorageFactory（按 type 选择）
   ruoyi.storage.type ─────→    ├─ local    → LocalStorageAdapter   （写本地磁盘）
                              ├─ minio    → S3StorageAdapter       （MinIO 端点）
                              ├─ oss      → S3StorageAdapter       （OSS 端点）
                              ├─ qiniu    → S3StorageAdapter       （七牛 S3 端点）
                              ├─ cos      → S3StorageAdapter       （COS 端点）
                              ├─ s3       → S3StorageAdapter       （AWS S3 端点）
                              └─ fastdfs  → FastDfsStorageAdapter   （需额外引入 SDK）
```

> `S3StorageAdapter` 用 MinIO 8.5.10 SDK 实现。MinIO 客户端**完全兼容 AWS S3 协议**，
> 所以一份代码适配 5 个云厂商，只换 `endpoint` 即可。

## 启用步骤

### 1. 启用 MinIO（推荐起步方案）

#### 1.1 docker 启动 MinIO

```bash
docker run -d --name minio \
  -p 9000:9000 -p 9001:9001 \
  -e MINIO_ROOT_USER=minioadmin \
  -e MINIO_ROOT_PASSWORD=minioadmin \
  -v /opt/minio/data:/data \
  minio/minio:RELEASE.2024-08-29T01-40-52Z \
  server /data --console-address ":9001"
```

#### 1.2 创建 bucket

访问 `http://localhost:9001`（账号 minioadmin / minioadmin），创建一个 bucket 例如 `wetangou`，
访问策略设为 `public`（允许公开读，前端可直接 `<img src=...>`）。

#### 1.3 改 application.yml

```yaml
ruoyi:
  storage:
    type: minio
    s3:
      endpoint: http://127.0.0.1:9000
      region: us-east-1
      bucket: wetangou
      access-key: minioadmin
      secret-key: minioadmin
      # public-domain: http://minio.example.com   # 可选：CDN 域名
```

重启后端，**所有 `/common/upload` 调用的上传自动走 MinIO**，返回 URL：
```
http://127.0.0.1:9000/wetangou/2026/08/02/12345.jpg
```

### 2. 启用阿里云 OSS

#### 2.1 阿里云控制台

- 创建 bucket 例如 `wetangou-prod`
- 读写权限：**公共读**
- 跨域设置：允许 `*` 来源 + 允许 GET/POST/PUT 方法
- 创建 AccessKey，记录 `AccessKey ID` 和 `AccessKey Secret`

#### 2.2 改 application.yml

```yaml
ruoyi:
  storage:
    type: oss
    s3:
      endpoint: https://oss-cn-shanghai.aliyuncs.com   # 你的 bucket 所在 region
      region: cn-shanghai
      bucket: wetangou-prod
      access-key: LTAIxxxxxxxxxxxxx
      secret-key: xxxxxxxxxxxxxxxxxxxxxxxx
```

重启后端，URL：
```
https://wetangou-prod.oss-cn-shanghai.aliyuncs.com/2026/08/02/12345.jpg
```

### 3. 启用七牛云

#### 3.1 七牛控制台

- 创建对象存储空间（**S3 兼容版本**），记录 endpoint：`https://s3-cn-east-1.qiniucs.com`
- 绑定自定义 CDN 域名，例如 `cdn.example.com`
- 创建 AccessKey / SecretKey

#### 3.2 改 application.yml

```yaml
ruoyi:
  storage:
    type: qiniu
    s3:
      endpoint: https://s3-cn-east-1.qiniucs.com
      region: cn-east-1
      bucket: your-bucket
      access-key: xxxxxxxxxxxxxxxxxxxxxxxx
      secret-key: xxxxxxxxxxxxxxxxxxxxxxxx
      public-domain: http://cdn.example.com   # CDN 域名，配置后 URL 走 CDN
```

URL：
```
http://cdn.example.com/2026/08/02/12345.jpg
```

### 4. 启用腾讯云 COS

```yaml
ruoyi:
  storage:
    type: cos
    s3:
      endpoint: https://cos.ap-shanghai.myqcloud.com
      region: ap-shanghai
      bucket: wetangou-1250000000   # 注意：bucket 名称必须带 APPID 后缀
      access-key: AKIDxxxxxxxxxxxxxxx
      secret-key: xxxxxxxxxxxxxxxxxxxxxxxx
```

### 5. 启用 AWS S3

```yaml
ruoyi:
  storage:
    type: s3
    s3:
      endpoint: https://s3.us-east-1.amazonaws.com
      region: us-east-1
      bucket: wetangou
      access-key: AKIAxxxxxxxxxxxxxxx
      secret-key: xxxxxxxxxxxxxxxxxxxxxxxx
```

## 故障排查

### 启动报错 "minio client 初始化失败"

```
java.lang.IllegalArgumentException: no endpoint specified
```

**原因**：`ruoyi.storage.s3.endpoint` 为空或 type 配错。

**修复**：检查 `application.yml` 的 `ruoyi.storage.type` 是否为 `local/minio/oss/qiniu/cos/s3/fastdfs` 之一。

### 上传报 "Access Denied"

**原因**：AccessKey 没写权限。

**修复**：
- 阿里云 OSS：RAM 用户需要 `AliyunOSSFullAccess`
- 七牛：AccessKey 需要有 bucket 的写权限
- MinIO：用 `mc admin policy set myminio readwrite user=minioadmin`

### 上传成功但 URL 访问 404

**原因**：bucket 不是公共读，或 public-domain 配错。

**修复**：
- MinIO bucket 访问策略设为 `public`
- 阿里云 OSS：bucket 读写权限 → 公共读
- 七牛：空间访问控制 → 公开

### URL 是 http 但 OSS bucket 是 https

**原因**：`public-domain` 没配，URL fallback 到 endpoint。

**修复**：`public-domain: https://cdn.example.com`

## 切换存储的影响

切换 `type` 后：

| 数据 | 影响 |
| --- | --- |
| 老的本地文件 | 保留在原磁盘，新文件走新后端 |
| 老的 OSS 文件 | URL 仍然有效，浏览器能访问 |
| 数据库的 url 字段 | 保留老 URL，新上传才有新 URL |

**混合存储**可行但需要**双写**，本方案不内置（需要改造 `SysFileServiceImpl.upload`）。

## 高级：私有读 bucket

如果 bucket 是**私有读**（不允许直接 `<img src=...>`），需要用预签名 URL：

```java
// 后端
String signedUrl = adapter.generatePresignedUrl(objectName, 3600);
// 前端 <img :src="signedUrl">
```

**Web 端使用**：返回给前端时用 `signedUrl`（1 小时有效），不直接用 `getPublicUrl`。
**小程序端**：用 `wx.downloadFile` 配合 signedUrl。
